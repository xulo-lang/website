## 概述

XULO 使用静态类型系统，支持局部类型推断。本节定义类型规则、子类型和 trait 解析语义。

## 类型种类

```text
base         string, boolean
numeric      number, int, float, i8..i64, u8..u64, f32, f64
generic      list<T>, map<K, V>, set<T>
option       T?  (T | null 的简写)
union        T | U
intersection T & U
struct       命名记录类型
enum         代数数据类型
trait        结构化能力契约
fn           函数签名
task         异步计算类型（Task<T>）
view         UI 组件返回类型（仅标记）
```

## 数值类型系统

XULO 采用**双层**数值类型设计：面向用户层追求简洁与 AI 友好，形式规范层提供精确的系统级控制。

### 面向用户层

| 类型 | 描述 | 默认用于 |
|------|------|---------|
| `number` | 通用数值（`int \| float` 的别名） | 快速原型、AI 生成代码 |
| `int` | 64 位有符号整数 | 整数字面量（`42`） |
| `float` | 64 位双精度浮点数 | 浮点字面量（`3.14`） |

### 形式规范层（固定位宽类型）

| 类型 | 位宽 | 范围 |
|------|------|------|
| `i8` | 8 位有符号 | -128 到 127 |
| `i16` | 16 位有符号 | -32,768 到 32,767 |
| `i32` | 32 位有符号 | -2^31 到 2^31-1 |
| `i64` | 64 位有符号 | -2^63 到 2^63-1 |
| `u8` | 8 位无符号 | 0 到 255 |
| `u16` | 16 位无符号 | 0 到 65,535 |
| `u32` | 32 位无符号 | 0 到 2^32-1 |
| `u64` | 64 位无符号 | 0 到 2^64-1 |
| `f32` | 32 位 IEEE 754 | ~7 位十进制精度 |
| `f64` | 64 位 IEEE 754 | ~15 位十进制精度 |

### 类型推断规则

```js
let x = 42            // 推断: int
let pi = 3.14         // 推断: float
let n: number = x     // number（int | float 联合）
let w: u32 = 800      // u32（从 int 强制转换）
let h: f32 = 0.8      // f32（从 float 强制转换）
```

- 整数字面量默认为 `int`；浮点字面量默认为 `float`
- `number` 是 `int | float` 的便捷别名 — 适用于 AI 生成代码和快速原型
- 赋值给固定位宽类型（`u32`、`f32` 等）时，字面量在范围内会被强制转换
- 混合类型算术（`int + float`）产生 `float`
- 固定位宽算术（`u32 + u32`）产生相同的固定位宽类型；字面量溢出为编译时错误，动态值溢出为运行时陷阱

### 结构体字段精度

对于 UI 和系统代码，固定位宽类型确保精确的内存布局：

```js
export pub struct ImageDimensions {
  width: u32,
  height: u32,
  opacity: f32,
}

export pub struct Color {
  r: u8,
  g: u8,
  b: u8,
  a: u8,
}
```

### FFI 兼容性

固定位宽类型直接映射到 C/Rust/WASM ABI 类型：

| XULO | C / Rust | WASM |
|------|----------|------|
| `i32` | `int32_t` | `i32` |
| `u32` | `uint32_t` | `i32`（无符号） |
| `i64` | `int64_t` | `i64` |
| `u64` | `uint64_t` | `i64`（无符号） |
| `f32` | `float` | `f32` |
| `f64` | `double` | `f64` |

## 类型推断

XULO 使用**局部类型推断** — 类型在函数体内推断，不跨函数签名推断。

```js
let x = 10            // 推断: int
let s = "hello"       // 推断: string
let list = [1, 2, 3]  // 推断: list<int>
let pi = 3.14         // 推断: float
```

导出函数**必须**显式标注返回类型：

```js
export fn add(a: int, b: int): int { a + b }
```

## 子类型

- `null` 是每个 `T?` 类型的子类型
- 具体类型 `T` 是 `T?` 的子类型
- 具有更多 `pub` 字段的结构体类型不是较少字段结构体的子类型（名义类型）
- `type` 别名使用结构类型

## 泛型类型推断

泛型类型参数在调用处推断：

```js
fn first<T>(list: list<T>): T { list[0] }

let n = first([1, 2, 3])    // T = int
let s = first(["a", "b"])   // T = string
```

不支持显式类型参数（`first<number>(...)`）。

## Trait 约束

类型参数可被约束：

```js
fn describe<T: Area>(t: T): float {
  Area.area(t)
}
```

解析规则：

1. `T: Trait` 在函数体内将 `T` 精化为 trait 的结构形状
2. 调度调用**必须**使用显式语法：`Trait.method(receiver)`
3. 泛型参数值在运行时被擦除 — 在 `T: Trait` 约束下**无法**进行调度调用

## Async / Await 类型规则

### Task 类型

所有 `async` 函数和闭包的返回类型在类型系统中统一表示为内置泛型 **`Task<T>`**。

| 语法 | 用户书写类型 | 实际求值类型 |
|------|------------|------------|
| `async fn foo(): T` | `T` | `Task<T>` |
| `async fn bar()` | （无返回类型） | `Task<void>` |
| `async (x: int): int => x + 1` | `int` | `Task<int>` |

### 函数签名自动包装 (Automatic Task Wrapping)

若函数或闭包被标记为 `async`，声明的返回类型为 `T`，则该函数或闭包求值后的实际类型为 `Task<T>`：

```text
async fn foo(): T   =>  foo: fn(): Task<T>
async () => expr    =>  该闭包类型: fn(): Task<T>
```

**函数体内部校验**：在 `async` 函数体内部，`return` 语句或隐式尾表达式的类型必须匹配 `T`（而非 `Task<T>`），编译器自动将其包装为 `Task<T>`。

### Await 解包规则 (Await Unwrapping)

- **操作数要求**：`await expr` 中的 `expr` 必须求值为 `Task<T>` 类型。
- **解包结果**：整个 `await expr` 表达式的类型为 `T`。
- **作用域限制**：`await` 只能出现在 `async` 函数或闭包体内（除非编译器开启 Top-level Await 支持）。

```text
await (Task<T>)  =>  T
```

### 内置 Task 工具方法

编译器在全局作用域内置 `Task` 命名空间：

| 方法 | 签名 | 说明 |
|------|------|------|
| `Task.all` | `all<T>(tasks: list<Task<T>>): Task<list<T>>` | 并行等待所有 Task 完成 |
| `Task.race` | `race<T>(tasks: list<Task<T>>): Task<T>` | 竞态等待第一个完成的 Task |
| `Task.resolve` | `resolve<T>(value: T): Task<T>` | 创建一个立即成功的 Task |
| `Task.reject` | `reject<T>(err: Error): Task<T>` | 创建一个立即失败的 Task |

## 类型兼容性

两个类型 `A` 和 `B` 兼容当：

- `A` 和 `B` 是同一类型
- `A` 是 `B` 的子类型
- 两者都是具有兼容参数和返回类型的函数类型
- 两者都是具有兼容字段类型的结构体类型（`type` 别名使用结构类型）

## 类型错误

编译器**必须**在编译时报告以下类型错误：

- 对不可变绑定的赋值
- 调用不可调用类型
- 结构体构造中缺少必需字段
- 非穷尽的 `match` 表达式
- 函数参数类型不匹配
- 在 `View` 函数外使用 `@State`/`@Store`/`@Effect`/`@Environment`
- 在非 `async` 函数/闭包内使用 `await`
- `await` 操作数的类型不是 `Task<T>`
- `async` 函数体内 `return` 的类型与声明的返回类型不匹配

## 模板字符串与插值

### 语法

```js
let name = "World"
let greeting = `Hello, ${name}!`                    // 插值表达式
let math = `1 + 1 = ${1 + 1}`                      // 表达式求值
let nested = `Value: ${if x > 0 { "positive" } else { "negative" }}`  // 块表达式
```

### 类型规则

**隐式类型转换 (String Coercion)**：任何基础类型（`int`, `float`, `boolean`, `string`）或实现了 `ToString` trait 的类型，在 `${expr}` 中求值时自动隐式转换为 `string`。

```js
let count = 42
let msg = `Count: ${count}`        // OK: int → string
let flag = true
let msg2 = `Flag: ${flag}`         // OK: boolean → string
let pi = 3.14
let msg3 = `Pi: ${pi}`             // OK: float → string
```

**复杂类型限制**：对于不具备可打印表示的复杂结构（如自定义 `struct` 或未实现显示协议的类型），在 `${expr}` 中传入将在编译时触发类型报错。

```js
struct User { name: string; age: int }
let u = User(name: "Alice", age: 30)
let msg = `User: ${u}`             // 编译错误: Type `User` does not implement string formatting
```

### 编译时优化

模板字符串在编译时可进行以下优化：
- 纯字面量连接：`` `Hello, ` + name + `!` `` → `` `Hello, ${name}!` ``
- 常量折叠：`` `1 + 1 = ${1 + 1}` `` → `` `1 + 1 = 2` ``

## 内置 `Math` 命名空间

`Math` 是 XULO 的内置命名空间，无需导入即可使用。包含最常用的数学函数和常量，编译器可直接将其映射为硬件指令或进行常量折叠。

### 使用示例

```js
// 常量
let circumference = 2 * Math.PI * radius
let halfPi = Math.PI / 2

// 基础运算
let hypotenuse = Math.sqrt(a * a + b * b)
let clamped = Math.min(Math.max(value, 0), 100)

// 三角函数
let x = Math.cos(angle) * radius
let y = Math.sin(angle) * radius

// 编译时常量折叠
let tau = Math.PI * 2  // 编译时求值为 6.283185307179586
```

### 编译器优化

- **常量折叠**：`Math.PI * 2.0` 在编译时直接求值为字面量
- **硬件指令映射**：`Math.sqrt` 可直接映射为 CPU 的 `SQRTSS`/`f64.sqrt` 指令
- **零调用开销**：内置函数无函数调用开销，直接内联

```js
let m = Matrix.new(3, 3)

```

## 内置 `Time` 命名空间

`Time` 是 XULO 的内置命名空间，提供高精度时间戳获取与异步休眠功能，无需导入即可使用。所有方法返回标量数值（`u64`），不引入复杂结构体或字符串对象。

### 方法

| 方法 | 签名 | 描述 |
|------|------|------|
| `Time.now` | `fn(): u64` | 获取当前 Unix 时间戳（毫秒） |
| `Time.now_nanos` | `fn(): u64` | 获取当前 Unix 时间戳（纳秒） |
| `Time.monotonic` | `fn(): u64` | 获取单调递增时间戳（毫秒） |
| `Time.monotonic_nanos` | `fn(): u64` | 获取单调递增时间戳（纳秒） |
| `Time.sleep` | `fn(ms: u64): Task<void>` | 异步休眠指定毫秒数 |

### 设计原则

- **纯粹与零开销**：原语层只输出标量数值（`u64`），不引入任何复杂结构体
- **硬件指令映射**：编译器可直接映射到 OS 内核 API（如 POSIX `clock_gettime` / WASM `clock_time_get`）
- **无需 AST 特殊处理**：`Time.now()` 被解析为普通的 `CallExpr`（Callee 为 `MemberExpr`）

### 使用示例

```js
// 获取当前时间戳
let timestamp = Time.now()           // Unix 毫秒时间戳
let nanos = Time.now_nanos()         // Unix 纳秒时间戳

// 性能测量
let start = Time.monotonic_nanos()
// ... 执行代码 ...
let elapsed = Time.monotonic_nanos() - start  // 纳秒级精度

// 异步休眠
spawn async {
    await Time.sleep(1000)           // 休眠 1 秒
    print("1 second later")
}

// 防抖/节流
let last_click = Time.monotonic()
// ... 处理点击事件 ...
if Time.monotonic() - last_click > 300 {  // 300ms 防抖
    // 执行操作
}
```

### 编译器优化

- **常量折叠**：如果 `Time.now()` 在编译时可求值（如测试场景），编译器可将其折叠
- **零调用开销**：内置函数无函数调用开销，直接映射到硬件指令
- **跨平台一致性**：所有 Target（Native、WASM）行为一致

### 高级时间库（标准库）

对于更复杂的时间操作（如时区转换、格式化），使用标准库模块：

```js
import { Instant, Duration, DateTime } from "std/time"

// 高精度时间戳
let instant = Instant.now()
let duration = Duration.from_millis(500)

// 日期时间格式化
let dt = DateTime.now()
let formatted = dt.format("YYYY-MM-DD HH:mm:ss")
```
