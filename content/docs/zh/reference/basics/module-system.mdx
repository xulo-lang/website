## 导入 / 导出

XULO 使用 `export` 控制模块级导出，使用 `pub` 控制类型内部成员可见性。

```js
// 导出（export 声明）
export fn add(a: number, b: number): number {
  a + b
}

export let PI = 3.14

export type User = {
  name: string
}

export enum Status {
  Active
  Inactive
}

// 重新导出当前模块已声明的名称
export { add, PI }

// 重新导出从其他模块导入的内容
export { add, PI } from './math'
export { default as Logger } from './logger'

// 导入
import { add, PI } from "math"
import type { User } from "types"
import * as math from "math"
import "core"
```

**导入形式：**

| 形式 | 含义 |
|------|------|
| `import { a, b as c } from "..."` | 命名导入 |
| `import type { T } from "..."` | 仅类型导入（运行时擦除） |
| `import * as ns from "..."` | 命名空间导入 |
| `import "..."` | 副作用导入 |

**导出形式：** 两种，全部以 `export` 开头——`export fn/let/type/enum`（声明级）、`export { a, b }`（名称再导出，可带 `from`）。

## `export` 关键字（模块级导出）

`export` 是声明级修饰符，把声明标记为公开（对其他模块可见）：

```js
export fn add(a: number, b: number): number { a + b }
export let PI = 3.14
export enum Status { Active Inactive }
export type User = { name: string }
```

- `export fn/let/type/enum` 只影响跨模块可见性，模块内照常使用
- `export { a, b }` 把本模块已声明的名称再导出
- `export { a, b } from './module'` 重新导出从其他模块导入的内容
- `export fn main`、`fn main` 都被识别为程序入口

> 注意：`import type` 写在 `import` 之后（`import type { ... }`），而非花括号内。
> `default` 关键字已移除并成为保留字（XULO 没有默认导出）；跨模块导出统一用 `export` 形态，导入统一按名称。

## 可见性与封装性规范

### 模块层级（Module Level）

使用 `export` 关键字控制类型、函数、常量是否对外暴露。未标记 `export` 的项仅在当前 `.xulo` 文件内可见。

```js
// 导出：其他模块可以 import
export struct User { ... }
export fn create_user(): User { ... }

// 私有：仅当前文件可用
struct InternalCache { ... }
fn helper(): string { ... }
```

### 类型内部层级（Member Level）

结构体（`struct`）的字段和方法**默认均为私有（Private）**。使用 `pub` 关键字显式将某个字段或方法标记为公有（Public）：

```js
export struct User {
    pub name: string     // 公有字段，外部可读写
    age: number          // 私有字段，仅限本模块内部访问
}

impl User {
    // 构造函数（外部可调用）
    pub fn new(name: string, age: number): User {
        User(name: name, age: age)
    }

    // 公有方法（外部可调用）
    pub fn get_age(self): number {
        self.age
    }

    // 私有方法（仅本文件可用）
    fn validate_age(age: number): boolean {
        age >= 0
    }
}
```

### 两个层面的分工

| 层面 | 关键字 | 控制目标 | 示例 |
| --- | --- | --- | --- |
| **模块层级** | `export` | 类型/函数/常量是否对外暴露 | `export struct User` |
| **类型内部** | `pub` | 字段/方法是否允许外部直接访问 | `pub name: string` |

**核心规则**：如果一个 `struct` 前面没有写 `export`，即使它的字段写了 `pub`，外部模块也根本导入不了这个 `struct`。

## 语言对照

| 概念 | 模块暴露 (Module Export) | 字段/成员封装 (Member Visibility) |
| --- | --- | --- |
| **XULO** | **`export`** | **`pub`**（默认私有） |
| **TypeScript** | `export` | `public` / `private`（默认 public） |
| **Swift** | `public` | `public` / `private` |
| **Rust** | `pub` (在文件/mod 层) | `pub` (在 struct 字段层) |

## 导入解析规则

- 相对路径或本地存在的模块名（如 `./math`、`math`）→ 解析为本地 `.xulo` 文件，参与打包
- 其余说明符（如 `@xulo/ui`）→ 视为外部包，原样生成 ESM `import`
- `import type` 只供类型检查；运行时仅当导入名同时是运行时值时保留其值绑定，否则完全擦除
- **无运行时模块加载器**：每个文件编译为一个返回导出对象的 IIFE，依赖按拓扑序内联进同一个 JS 文件
- 循环导入（A → B → A）会被拒绝

## 跨模块调用

- 导入的函数保留参数名，支持具名实参调用
- 导入不存在的导出名报语义错误
- `trait` 是可导出的类型成员（`export trait`），用 `import type { Trait } from "./mod"` 引入；`impl` 块不跨模块移植，需在引用该特征的模块内本地声明
