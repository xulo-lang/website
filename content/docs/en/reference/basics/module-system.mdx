## One File, One Module

A Xulo module **is** a file (`.xulo`): there is no module header, no module block, and no directory module. The file's contents are the whole module, and everything in file scope marked `pub` forms its interface.

A file is a sequence of top-level declarations — `fn`, `struct`, `enum`, `trait`, `impl`, `type`, `let`, `const`, `import`, and `pub use` — and **`import` declarations must form the file's header**, before every other top-level declaration (`E0605`).

```js
import { add, PI } from "math"
import * as m from "util"
import type { User } from "types"

pub struct Account { owner: User, balance: Int }

pub fn deposit(a: Account, amount: Int): Int {
  a.balance + amount
}
```

## Import Forms

There are exactly four:

| Form | Meaning |
|------|---------|
| `import { a, b as c } from "m"` | named import; `as` renames the local binding only |
| `import * as ns from "m"` | namespace import; members selected with `ns.a` |
| `import type { T } from "m"` | type-only import, erased at runtime |
| `import "m"` | side-effect import; binds nothing, forces initialization order |

```js
import { add, add as plus } from "math"
import * as math from "math"
import type { User, Status } from "types"
import "core"
```

- The `type` modifier follows `import` — `import { type User }` is not a form.
- A type-only binding may be used in type positions and as the base of an enum-variant path (`Status::Active`), but never where a value is expected (`E0606`).
- Every imported name must exist (`E0601`) and be exported (`E0602`); two imports binding the same local name are a duplicate (`E0104`). An import never used in the module is reported as `W0102`.
- `import` appears only at file scope — never inside a function, block, or component body.

## Exports: `pub`, Not `export`

Xulo has **no `export` keyword** — `export` is a reserved word. A declaration is exported by marking it `pub`, and names are re-exported with `pub use`:

```js
pub fn add(a: Int, b: Int): Int { a + b }
pub struct User { pub name: String, age: Int }
pub enum Status { Active, Inactive }
pub trait Shape { fn area(self): Float }
pub type Score = Int
pub const PI = 3.14
pub let appName = "xulo"

pub use { add, PI }                      // names of this module
pub use { User, Status } from "types"    // names read from another module
```

| Declaration | Exported name | What importers receive |
|-------------|---------------|------------------------|
| `pub fn f(…)` | `f` | a function of the declared signature |
| `pub struct S { … }` | `S` | the type, its constructor, its `pub` members |
| `pub enum E { … }` | `E` | the type and its variants `E::V` |
| `pub trait T { … }` | `T` | the trait, to be implemented locally |
| `pub type A = …` | `A` | the transparent alias |
| `pub let x` / `pub const K` | `x` / `K` | the binding and its declared type |
| `pub use { a, b }` | `a`, `b` | the interface names of this module |
| `impl …` | — | never exported; an `impl` has no name |

- `pub use { x } from "m"` is a pure forwarding edge: it does not bind `x` locally.
- **Importing does not re-export.** A name a module imports is part of its view, not its interface, unless it is also `pub use`d.
- `main` is an ordinary module-level `fn` (see [Entry Point](#entry-point)); it may optionally be marked `pub`.

## Specifiers and Resolution

A specifier is a string literal resolved to exactly one file:

```js
import { area } from "./shapes"        // ./shapes.xulo
import { fmt } from "../lib/util"      // ../lib/util.xulo
import { hstack } from "@xulo/ui"      // package specifier
```

- **Relative specifiers** start with `./` or `../`, are resolved against the importing file's directory, and the `.xulo` extension is implied — never written.
- A specifier resolves to a **file**: `./lib` means `lib.xulo`, never `lib/mod.xulo` or `lib/index.xulo`. There are no directory modules.
- **Package specifiers** (anything without a `./` or `../` prefix) are mapped by the package environment, which is determined outside the language; what the language requires is that each resolves to exactly one module regardless of which file asks.
- A specifier that resolves to nothing, to a non-file path, or to more than one candidate is `E0607`.

## Cycles

Each `import` and each `pub use { … } from "…"` is an edge in the dependency graph. A cycle — direct, two-step, or longer — is a compile-time error (`E0603`), and the diagnostic names the path in order (`a.xulo → b.xulo → a.xulo`). A cycle has no topological initialization order.

## Visibility

Every declaration is **module-private unless marked `pub`**:

```js
// math.xulo
pub fn add(a: Int, b: Int): Int { a + b }
fn helper(n: Int): Int { n }

// main.xulo
import { add, helper } from "math"    // error: `helper` is not public (E0602)
```

- **Core rule:** if the type itself is not `pub`, its `pub` members do not help — a module that cannot import `User` cannot reach `User.name`.
- Struct fields and methods are private by default; `pub` on a member opens it to modules that can already see the type. Reads and writes are both controlled.
- Enum variants carry no modifier: they ride on the enum's visibility. Trait methods do the same for their trait.
- There is no `pub impl`: an `impl` introduces no name. Each method's own `pub` decides whether it is callable from other modules.
- A nested `fn` is block-local and cannot be marked `pub`.
- A `pub` signature must not expose a private type (`E0604`) — otherwise an importer would obtain values it cannot name.

## Declaration Order

- Module-level `fn`, `struct`, `enum`, `trait`, `type`, and `impl` may reference each other **in any order**; forward references and mutual recursion are legal.
- Module-level `let`, `let mut`, and `const` must be declared before use (`E0101`); their initializers run in declaration order.
- Inside a body the stricter block rule always applies: locals are not hoisted.

## Entry Point

An executable program's entry module declares a module-level `main`:

```js
fn main() { … }            // headless program: Unit
fn main(): View { … }       // renderable program
async fn main() { … }       // asynchronous program: Task<Unit>
```

`main` takes no parameters, its return type is omitted or `View` (anything else is `E0609`), it may be `async`, and it may be marked `pub`. A program whose entry module declares no `main` is `E0608`.

## Error Summary

| Code | Violation |
|------|-----------|
| `E0601` | import/re-export names a member the target does not have |
| `E0602` | import names a private member, or a `pub` rule is broken |
| `E0603` | import or re-export cycle |
| `E0604` | a `pub` signature exposes a private type |
| `E0605` | `import` outside the file header |
| `E0606` | a type-only binding used where a value is expected |
| `E0607` | specifier unresolvable or ambiguous |
| `E0608` / `E0609` | missing or malformed `main` |
| `E0104` | two bindings for one local name |
| `W0102` | an imported name is never used |

Cross-module rules in full are in the [import/export spec](/en/docs/spec/modules/import-export/) and the [visibility spec](/en/docs/spec/modules/visibility/).
