## Function Definition

```js
// No return value
fn log(message: string) {
  print(message)
}

// With return value (implicit return)
fn add(a: int, b: int): int {
  a + b
}

// Explicit return
fn subtract(a: int, b: int): int {
  return a - b
}
```

**Rules:**

- Use the `fn` keyword
- Parameter types use `:`
- Return types use `:`
- Last expression without semicolon = implicit return; **when a return type is declared, the trailing expression must match it**
- `return` for explicit return is also supported
- Omit the return type when there is no return value

## Parameters

### Optional Parameters (`?`)

```js
fn greet(name: string?): string {
  if name != null {
    "Hello, " + name
  } else {
    "Hello, stranger"
  }
}

greet()      // OK, name = null
greet("A")   // OK
```

### Default Parameter Values (`=`)

```js
fn greet(name: string = "stranger"): string {
  "Hello, " + name
}
```

### Named Parameters

```js
fn Button(label: string, variant: string = "primary"): View

Button(variant: "outline", label: "Submit")  // Named args, can be out of order
```

- Call-site named arguments `greet(name: "X")` are supported; once named arguments are used, all arguments must be named, and they can be out of order
- String literal union types (`type Status = "active" | "inactive"`) accept the corresponding literals at call sites

## Generic Functions

```js
fn first<T>(list: list<T>): T {
  list[0]
}

// Type argument inferred at call site: first([1, 2, 3]) binds T to int
let n: int = first([1, 2, 3])
let s: string = first(["a"])      // OK, T = string
let bad: string = first([1, 2])   // Error, T inferred as int
```

> Explicit type arguments (`first<number>(...)`) are **not** supported. Generic type parameters are always inferred at the call site.

## Closures

Closures are anonymous functions written with `=>`. They capture outer scope variables automatically (equivalent to JS closures). Use `fn` only for named declarations.

```js
fn apply(f: fn(int): int, x: int): int {
  f(x)
}

fn makeAdder(n: int): fn(int): int {
  (v: int): int => v + n   // Captures n
}

fn main() {
  let double = (x: int): int => x * 2

  let add5 = makeAdder(5)
  print(apply(double, 3))   // 6
  print(add5(10))           // 15

  // Async closure
  let work = async () => 42
  let v = await work()      // 42
}
```

### Syntax Forms

#### Single-line Expression Closures (Type Inferred)

```js
let add = (a, b) => a + b
let numbers = list.map([1, 2, 3], (x) => x * 2)
```

#### Multi-line Block Closures (With Explicit Types and Return Type)

```js
let handler = (event: MouseEvent): boolean => {
    if event.is_valid {
        return true
    }
    false
}
```

#### Closure Type Descriptors (For Function Parameter Type Annotations)

`fn(InputType): OutputType`

```js
pub fn filter<T>(items: list<T>, predicate: fn(T): boolean): list<T> {
    // ...
}
```

### EBNF Formal Rules

```text
ClosureExpr      = [ 'async' ] ClosureParams [ ':' Type ] '=>' ( Expression | Block ) ;
ClosureParams    = Identifier
                 | '(' [ ClosureParam ( ',' ClosureParam )* ','? ] ')' ;
ClosureParam     = Identifier [ ':' Type ] ;

ClosureType      = [ 'async' ] 'fn' '(' [ TypeList ] ')' [ ':' Type ] ;
```

### Rules

- `fn` is reserved for named function/method declarations; `=>` is for anonymous closures
- Closure type is `fn(param types): return type`, assignable to parameters/variables with that type
- Automatically accesses outer local variables through capture; mutable captures can modify outer `let` bindings directly
- Function values are called with positional arguments only; the count must match exactly; named arguments are not supported
- Function values can be called from any expression: `xs[0](10)`, `getFn()(x)`, `(f)(5)`
- Async closures are written as `async () => ...`, return a Promise when called, and can be `await`ed
