## Definition

```js
// no return value: the type is Unit
fn log(message: String) {
  print(message)
}

// implicit return: the trailing expression
fn add(a: Int, b: Int): Int {
  a + b
}

// explicit return
fn subtract(a: Int, b: Int): Int {
  return a - b
}
```

**Rules:**

- The form is `fn name(p: T, q: U): R { … }`. Every parameter is annotated; parameter types are never inferred from arguments.
- An omitted return type means `Unit`; writing `: Unit` is equivalent. When a return type is declared, the trailing expression (or every `return` operand) must match it (`E0203`).
- `return` without a value is legal only when the declared return type is `Unit`; `return` outside a function or closure body is `E0214`.
- A trailing `;` discards the block's value — `fn g(): Int { 42; }` is an error.
- Functions are not overloaded: a second declaration of the same name in one scope is a duplicate-declaration error.

```js
fn show(x: Int) { print(x) }
fn show(x: String) { print(x) }   // error: duplicate name
```

## Scope, Recursion, Forward References

- Module-level `fn`, `struct`, `enum`, `trait`, `type`, and `impl` are in scope throughout the file: a function may call one declared later, and mutual recursion needs no ordering.
- Module-level `let`/`const` are the exception — they must be declared before use.
- A nested `fn` is local to its block: it may recurse on itself, but two nested functions do not forward-reference each other, and `pub` does not apply to them.
- Recursion has no static depth limit; exhausting the stack or task limit is a runtime failure.

## Parameters

```js
fn greet(name: String = "stranger"): String { "Hello, " + name }
fn maybe(id: String?): String { id ?? "none" }
fn render(text: String, size: Int, bold: Boolean): View { Text(text) }

fn main() {
  render("Hi", bold: true, size: 14)   // positional, then named
  render(text: "Hi", 14, bold: true)   // error: positional after named
  render("Hi")                         // error: required parameter missing
}
```

- Parameters are required unless they declare a default with `=` or have an optional type `T?`. An omitted optional parameter binds to `null`.
- A default is evaluated at each call that omits it, and the parameter's type must admit the default (`E0228`).
- **Named arguments** write `label: expression`. Positional arguments come first — once a named argument appears, every following argument must be named. Named arguments may be reordered; an unknown or repeated label, or a positional argument after a named one, is `E0208`, and a wrong argument count is `E0207`.
- Calls through a function **value** (`fn(…)`) accept positional arguments only, with an exact count.

## Closures

There are two closure forms; both are expressions of function type `fn(A): R`.

```js
// function expressions reuse the declaration shape without a name
let double = fn(x: Int): Int { x * 2 }

// arrow closures: parameters, optional result, =>, body
let add = (x: Int, y: Int) => x + y
let addTyped: fn(Int, Int): Int = (x, y) => x + y   // types from the expected type
let one = x => x * 2                                // single parameter: parens optional
let nothing = () => print("hi")                     // empty list must be written ()
let classify = (n: Int): String => {                // block body
  if n > 0 { "positive" } else { "not positive" }
}
```

- Parameter annotations may be omitted only when an **expected type** supplies them — as a call argument, a typed binding initializer, or a typed `return`. Without one, annotations are required.
- The result annotation `: R` is optional; when present it must agree with the body.
- Capture is **by reference** and implicit: no capture list exists, and there is no `move` modifier in a parameter list. A closure may assign to a captured binding only if it was declared `let mut` (`E0401`) — a `mut` parameter or `mut self` is assignable directly but **read-only inside a closure**, so a closure cannot mutate the caller's place through a borrowed receiver.
- A closure body must not refer to the closure being defined — recursion needs a named `fn`.
- An immediately-invoked closure is parenthesized: `((x: Int): Int => x + 1)(41)`.

```js
fn makeAdder(n: Int): fn(Int): Int {
  (v: Int) => v + n            // read capture of n
}

fn main() {
  let add5 = makeAdder(5)
  print(str(add5(10)))         // 15
  print(apply(x => x * 3, 7))  // expected type supplies x
}
```

```js
struct Counter { value: Int }

fn broken(p: mut Counter): fn(): Unit {
  fn(): Unit { p.value = p.value + 1 }   // error: `p` is not declared `let mut` (E0401)
}

fn ok(p: Counter): fn(): Int {
  fn(): Int { p.value }                  // ok: read capture
}
```

## Async Functions

```js
async fn doubleAsync(n: Int): Int {
  await Task.resolve(n * 2)
}
async fn main() { print(await doubleAsync(21)) }   // 42
```

- `async fn` declares its **result** type; the function's evaluated type is `fn(…): Task<T>` — not `Promise`.
- Calling it starts the body immediately; `await` unwraps `Task<T>` to `T` and is legal only inside `async` bodies.
- Inside the body, the trailing expression and every `return` operand have type `T`, not `Task<T>` — wrapping is automatic.
- Async closures are written `async (x: Int): Int => …` or `async fn(x: Int): Int { … }`; calling them returns `Task<T>`.

## Inference Boundary

- **Named declarations are fully annotated**: every parameter type, and the return type whenever the function produces a value. Only an omitted return type (`Unit`) may be missing.
- Local `let` bindings infer from their initializer.
- **Closure parameters** may omit annotations only where an expected function type provides them.

```js
fn apply(f: fn(Int): Int, x: Int): Int { f(x) }
let double = (x: Int): Int => x * 2          // annotation required
print(str(apply(x => x * 3, 7)))             // optional: the parameter type is known
```

## Methods and `self`

```js
struct Counter { value: Int }

impl Counter {
  fn increment(mut self) { self.value = self.value + 1 }
  fn get(self): Int { self.value }
}

fn main() {
  let mut c = Counter(value: 0)
  c.increment()
  print(str(c.get()))            // 1
  let maybe: Counter? = null
  print(maybe?.get())               // null: the call is not evaluated
}
```

- Methods live in an `impl` block. The first parameter is the receiver, written `self` (immutable borrow) or `mut self`; a method that assigns to `self` or a field must declare `mut self`.
- At the call site the receiver is not written as an argument: `c.increment()` supplies `c`.
- **Resolution order:** `value.method(…)` resolves first to an inherent method of the receiver's type, otherwise to a trait method from an implementation in scope. Exactly one candidate must result — none is `E0102`, more than one is `E0809` and must be disambiguated with explicit dispatch `Trait.method(receiver)`.
- A receiver that may be `null` uses optional chaining: `receiver?.method()` evaluates to `null` instead of calling.

## Trait Methods

```js
trait Greet {
  fn greeting(self): String;
  fn farewell(self): String
}
```

Trait methods are signature-only, separated by `;`, and **must** declare a return type (an omitted one is not `Unit` here). An `impl Trait for Type` must provide every declared method with mutually assignable signatures, and may not add extras. See [Generics & Traits](/en/docs/reference/basics/generics-and-traits/).

## Generic Functions

```js
fn first<T>(xs: List<T>): T { xs[0] }
fn areaOf<T: Area>(shape: T): Float { Area.area(shape) }
fn perimeterOf<T>(shape: T): Float where T: Area { shape.perimeter() }

fn main() {
  let n = first([1, 2, 3])        // T = Int
  let s = first(["a", "b"])       // T = String
}
```

Type arguments are always inferred — `first<Int>(…)` is not part of the language — and every inferred argument must satisfy the parameter's bounds. Inline `<T: …>` and `where T: …` are equivalent; multiple bounds are joined with `+`.

Full rules for generics, traits, and dispatch are in [Generics & Traits](/en/docs/reference/basics/generics-and-traits/); the declaration and parameter forms are specified in the [functions spec](/en/docs/spec/functions/).
