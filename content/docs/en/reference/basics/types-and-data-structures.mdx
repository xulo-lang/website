## Base Types

```js
bool        // true | false
string         // immutable UTF-8 text
int            // 64-bit signed integer
float          // 64-bit IEEE-754 float
number         // int | float
null           // only value: null
unit           // the type of "no meaningful value"
unknown        // top type: every type fits it
View           // marker type returned by components
Range<T>       // produced by ..< and ...
i8..u64, f32, f64   // fixed-bit numeric types
usize, isize   // pointer-width integers (W bits: the platform pointer width)
Ptr            // opaque foreign handle (FFI only: no literal, no cast)
```

Literals pick their type by form: `42`, `0xff`, `0b1010`, `0o77` are `int`; `3.14` is `float`; `"hi"`, `'hi'`, and `` `hi ${x}` `` are `string`; `true`/`false` are `bool`.

- **No truthiness.** Numbers are not booleans: `if 0 { … }` is an error (`E0201`).
- **Strings are not indexable.** `s[i]` is an error (`E0215`); inspection is done with the prelude functions `stringSize`, `stringCodeAt`, and `stringSlice`, and bytes are reached with `stringBytes`. Only `"..."`/`'...'` and backtick templates interpolate.
- **No implicit conversion.** `"count=" + 1` is an error (`E0227`) — write `` `count=${n}` `` or `str(x)`.
- **`number` is a union**, not a default: `int` and `float` promote to `float` in mixed arithmetic, and a `number` is not assignable to `int` or `float` without a check.
- **Fixed-bit types keep their own type.** `i8`…`u64`, `f32`, `f64`, `usize`, and `isize` never convert to the user-facing layer or to another width (`E0201`); `usize`/`isize` have the platform's pointer width, which an implementation defines and must document.
- **`Ptr` exists only at the FFI boundary.** It has no literal, no cast, and no type arguments, and it is reserved like any other built-in name; it is covered with the rest of the foreign interface in [FFI & Interop](/en/docs/reference/ecosystem/ffi-and-interop/).
- The built-in names (`bool`, `string`, `int`, `float`, `number`, `List`, `Map`, `Set`, `Result`, `View`, `Ptr`, …) are reserved; redeclaring one at module scope is an error (`E0106`).

## Collections and Tuples

```js
let xs = [1, 2, 3]               // List<int>
let user = { name: "lyy" }        // Map<string, string>
let p = (10, "ten")               // (int, string)
```

- `List<T>` is an ordered sequence addressed by `xs[i]`; `[]` needs an expected type (`E0216`).
- `Map<K, V>` is insertion-ordered; keys must be hashable (`string`, `int`, `float`, `bool`, payload-free enums). A brace literal `{ k: v }` is a **map**, not an anonymous struct.
- `Set<T>` has no literal form — construct it with the prelude — and no specified iteration order.
- Tuples have at least two elements, are read with `p.0`, and destructure with `let (a, b) = p`. They cannot be iterated (`E0213`) and have no `match` pattern form.
- Beyond `+`, subscripts, and iteration, collections are manipulated with prelude operations: `listSize`, `listPush`, `listRemove` (out-of-range yields `null`), and `enumerate` on lists; `mapSize`, `mapHasKey`, `mapGet` (a lookup that answers `null` instead of failing), `mapRemove`, and entry conversions on maps; `setFromList`, `setInsert`, `setRemove`, `setContains`, and `setSize` on sets.

## Optionals, Unions, Intersections

```js
let name: string? = null          // T? is exactly T | null
let which: string | int = 1
fn draw(x: Area & Scalable) {}    // & joins traits only
```

- An optional must be checked, narrowed with `!= null`, unwrapped with `?.`/`??`, or propagated with `?` before it is used where `T` is required (`E0201`).
- `T | U` is tested with `match` or `is`; literal types may be union members (`type Status = "active" | "inactive"`).
- `T & U` accepts only trait types — two structs or a struct and a trait intersect in nothing (`E0226`).

## Type Aliases

`type Name = T` names an existing type; it introduces no new one.

```js
type Status = "active" | "inactive" | "pending"
type Handler = fn(string): int
type Wrapper<T> = List<T>
type ApiResponse<T> = { data: T?, error: string? }   // object type in type position
```

- An alias is transparent: `Status` and its right-hand side are the same type everywhere.
- No `impl`, method, or trait implementation may be declared *for an alias* — implementations attach to the type it expands to.
- Aliases may be generic and may be exported with `pub`.
- An alias cycle (`type A = B` with `type B = A`) is an error (`E0105`).

## Structs

A `struct` is a nominal record: named fields, each with a declared type.

```js
struct User {
  name: string
  age: int
  email: string?
}

fn main() {
  let alice = User(name: "Alice", age: 30)
  let mut bob = User(name: "Bob", age: 25, email: "bob@example.com")
  bob.age = 26
  print(alice.name)          // Alice
}
```

**Rules:**

- Construction uses named arguments. Every non-optional field is required (`E0205`); an optional field may be omitted and is then `null`.
- Fields are accessed with `.`. Assigning to a field requires a mutable base — `let mut` or a `mut` parameter — otherwise `E0401`.
- Structs are nominal: two declarations with identical fields are still unrelated types, and a struct never converts to or from a `Map`.
- Field types compose into the struct's value: the declaring type must not be reachable from its own fields through field positions, tuple elements, and alias expansion without an intervening indirection — `List<T>`, `Map<K, V>`, `Set<T>`, `T?`, a function type, or an enum payload. `struct Node { node: Node }` and the mutual pair `struct A { b: B }` / `struct B { a: A }` are errors (`E0113`); `struct Node { next: Node?, children: List<Node> }` is well-formed.
- Structs do not inherit. Shared behavior is attached with `impl` blocks and `trait` implementations.
- Fields are private by default; `pub` opens one field to modules that can already see the struct. Reading, writing, or constructing a private field from another module is `E0602`.
- Structs may be generic: `struct Pair<A, B> { first: A, second: B }`.

### Methods

```js
struct Rectangle {
  w: float,
  h: float
}

impl Rectangle {
  fn area(self): float { self.w * self.h }
  fn is_square(self): bool { self.w == self.h }
}

fn main() {
  let r = Rectangle(w: 3.0, h: 4.0)
  print(str(r.area()))       // 12
}
```

`self` (or `mut self` for a method that assigns) is an explicit first parameter; at the call site only `r.area()` is written. Method resolution and visibility are covered in [Functions](/en/docs/reference/basics/functions-and-methods/).

### Structs vs Aliases vs Maps

| | `struct` | `type` alias | `Map<K, V>` |
|---|---|---|---|
| Identity | nominal, one type per declaration | transparent — the right-hand side | structural, depends on `K`/`V` |
| Values built by | constructor `User(…)` | whatever the right-hand side allows | brace or `Map<K, V>{ … }` literal |
| `impl` / traits | yes | never on the alias itself | no |
| Fields | fixed names, `pub` visibility | follows the right-hand side | dynamic hashable keys |

Use a `struct` when a type needs methods, trait implementations, field visibility, or a distinct identity; use a `Map` for dynamic key–value data.

## Enums

An `enum` declares a nominal type and a fixed set of variants, each optionally carrying a payload.

```js
enum Theme {
  Light,
  Dark,
  System
}

enum Shape {
  Circle(float),
  Rect(width: float, height: float)
}
```

- Commas between variants are optional; trailing commas are allowed.
- Variants are written with `::` — `Theme::Dark`, `Shape::Circle(2.0)` — never `Theme.Dark`. `.` is reserved for fields and methods.
- Payloads are constructed positionally: `Shape::Rect(3.0, 4.0)`. A named payload form (`width: float`) labels the slots for documentation only; it is not a named argument.
- A variant payload may mention the enum being declared: `enum Tree { Leaf(int), Node(Tree, Tree) }` is well-formed — payload recursion needs no indirection, and the field-composition cycle rule (`E0113`) governs struct fields only.
- Within one variant all slots use the same form; across variants the forms may be mixed.
- The value has the enum type — `Shape::Circle(2.0)` is a `Shape`, not a variant-specific type.
- `match` over an enum must be exhaustive (`E0301`); see [Control Flow](/en/docs/reference/basics/control-flow-and-matching/).
- `pub enum` exports the enum; variants carry no modifier of their own and ride on the enum's visibility.

```js
let shape = Shape::Circle(2.0)
let label = match shape {
  Shape::Circle(r) => `circle ${r}`
  Shape::Rect(w, h) => `${w}x${h}`
}
```

## Traits

A `trait` declares method signatures — a capability that types opt into with an `impl`.

```js
trait Area {
  fn area(self): float;
  fn perimeter(self): float
}

struct Rectangle { w: float, h: float }

impl Area for Rectangle {
  fn area(self): float { self.w * self.h }
  fn perimeter(self): float { 2.0 * (self.w + self.h) }
}
```

- Methods inside a trait are **separated by `;`** (a trailing `;` is optional), are signature-only, and each must declare a return type.
- There are no default methods: an `impl` must provide **every** declared method, with matching signatures, and may not add extra ones.
- Calls use explicit dispatch — `Area::area(r)` — or, for a member call, the resolution order inherent methods first, then trait implementations in scope.
- Satisfaction is **nominal**: only an `impl` makes a type implement a trait; matching field shapes never does.
- `pub trait` exports the trait; importers normally bring it in with `use type form::Area;` and implement it locally — `use`-ing a trait never brings an `impl`.
- `ToString` is built in: interpolating a value in a template requires a base type or `impl ToString` (`E0212`).

Bounds, generics, and dispatch are specified in [Generics & Traits](/en/docs/reference/basics/generics-and-traits/). Base types, optionals, and collections follow the [type spec](/en/docs/spec/types/primitive-types/).
