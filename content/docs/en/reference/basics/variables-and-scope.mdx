---
title: Variables & State
description: Variable bindings, reactive state, and effects in XULO.
---

XULO has two kinds of bindings: ordinary bindings (`let` / `let mut` / `const`) and component state (`@State` / `@Store` / `@Environment` / `@Effect`).

## Variable Bindings

```js
let count = 0                 // immutable
let mut x = 10                // mutable
let name: String = "Alice"    // annotated
let maybe: String? = null     // optional type
let total := 0                // sugar for: let mut total = 0
const APP_NAME = "Xulo"       // compile-time constant
```

**Rules:**

- `let` is immutable; assigning to it is an error (`E0401`). `let mut` is mutable, and `let x := expr` desugars to `let mut x = expr`.
- The annotation is written after the name with `:`. Without it the type is inferred from the initializer; when the initializer does not determine the type — an empty list literal — the annotation is required (`E0216`).
- **Initialization is required**: there is no uninitialized binding, and every `let` is initialized in its own statement.
- `const` takes a constant expression — a literal, another `const`, or arithmetic/comparison over them. A function call is not a constant expression.
- There is no compound assignment: no `+=`, `-=`, or `++`. Write `n = n + 1`.

| Form | Mutable | Use |
|------|---------|-----|
| `let x = 1` | no | values that never change |
| `let mut x = 1` | yes | values that are reassigned |
| `let x := 1` | yes (sugar for `let mut`) | short mutable binding |
| `const K = 1` | no | compile-time constants |

## Destructuring

```js
struct Person { name: String, age: Int }

let person = Person(name: "Alice", age: 30)
let { name, age } = person         // struct fields

let p = (10, "ten")
let (n, label) = p                 // tuple positions
let (first, _) = p                 // _ discards an element
```

- Struct destructuring binds one level of fields, each as an immutable binding of the same name; there is no rename form. A missing field is an error (`E0206`).
- Tuple destructuring requires the name count to match the arity (`E0219`); there is no `let mut (a, b)` form.
- Map, list, and enum values are not deconstructed with `let` — use subscripts and `match`.

## Assignment

```js
let mut x = 10
x = x + 1

let mut xs = [1, 2, 3]
xs[0] = 9
```

- The target must be a place expression backed by a `mut` binding (or a field/subscript reached through one); anything else is `E0401`.
- The right-hand side is evaluated first, then the place's receiver and index, then the write happens. The result of an assignment is `Unit`.
- Assignment is a **statement** — it produces no value to use.

## Scopes

| Scope | Introduced by | Names visible |
|-------|---------------|---------------|
| Module | the module body (file or inline `mod` block) | top-level declarations plus every `mod`, `use`, and `pub use` binding |
| Function | a `fn` header | parameters, then the body |
| Generic parameter | `<T>` or `where T: …` | in the signature, return type, and body |
| Block | every `{ … }` | declarations made inside that block |
| Closure | `fn() { … }` or `=> …` | its parameters plus everything captured at creation |
| Pattern | a `match` arm pattern | bindings of that arm only |

**Declaration order decides visibility:**

- Locals are **not hoisted**: a binding is in scope from the end of its declaration to the end of the enclosing block, so reading it earlier is `E0101`.
- Module-level `fn`, `struct`, `enum`, `trait`, `type`, and `impl` are in scope throughout the whole file, in any order — forward references and mutual recursion are legal.
- Module-level `let`, `let mut`, and `const` must be declared before use; their initializers run in declaration order.

```js
fn main() {
  let a = helper()   // legal: module-level fn may be declared later
  print(a)
}
fn helper(): Int { 42 }
```

## Shadowing and `_`

- A declaration in an **inner** block may shadow an outer name; two declarations of the same name in the *same* block are a duplicate error (`E0103`).
- Shadowing never re-points a name a closure already captured — a captured binding keeps its original value.
- `_` is the wildcard: it matches anything, binds nothing, and cannot be assigned or read. It is not an identifier.
- A binding that is never read is reported as `W0101`; a `pub` declaration, a `const`, a parameter, and `_` are never reported.

```js
let x = 1
let read = fn(): Int { x }   // captures the outer x
if true {
  let x = 2                  // shadows only inside this block
  print(str(x))              // 2
}
print(str(read()))           // still 1
```

Naming conventions (recommended, not enforced): UpperCamelCase for types and components, lowerCamelCase for functions and variables, `UPPER_SNAKE_CASE` for constants, single letters for type parameters.

## Local State `@State`

```js
fn Counter(): View {
  @State let count: Int = 0

  VStack {
    Text(`count = ${count}`)
    Button("More", onClick: fn() { count = count + 1 })
  }
}
```

- Declared only at the top level of a component body — a `fn` whose declared return type is `View` — and nowhere else (`E0701`).
- **Implicitly mutable**: assignment needs no `mut`, and each assignment schedules the component to re-run. There is no `@State let mut`.
- The initializer runs when the instance is created, not on every run; the value is retained across re-runs and is per instance — two `Counter()`s never share a `count`.

## Global State `@Store`

```js
fn Home(): View {
  @Store let { user, theme } = useAppStore()
  @Store let { setTheme } = useAppStore()

  VStack {
    Text(`signed in as ${user?.name ?? "guest"}`)
    Button("Toggle theme", onClick: fn() { setTheme(Theme::Dark) })
  }
}
```

- A `@Store` declaration destructures a shared store; the names inside `{ … }` behave exactly like `@State` bindings.
- Store values are program-wide: an update re-runs every component that declared `@Store` for that store, while their own `@State` cells are untouched.
- The initializer is an ordinary expression (`useAppStore()` above is a library function, not a language intrinsic).

## Environment `@Environment`

```js
fn Nav(): View {
  @Environment let router: Router

  Button("About", onClick: fn() { router.push("/about") })
}
```

- The form is `@Environment let name: T` with **no initializer** — the value is provided from outside the program.
- The type annotation is **required** (`E0710`); nothing else in the declaration supplies it.
- The nearest enclosing provision wins; reading a key that was never provided is a runtime failure.

## Side Effects `@Effect`

```js
fn Counter(): View {
  @State let count: Int = 0

  @Effect fn() { print("mounted") }            // every re-run
  @Effect fn() { fetch(id) }, [id]             // on mount and when `id` changes

  Text(str(count))
}
```

- The form is `@Effect fn() { … }` — an unnamed closure of type `fn(): Unit` (`E0709` for any other return type), optionally followed by `, [deps]`.
- The dependency list must be a **list literal** (`E0708`); with it, the effect runs on mount and whenever a listed value changes, not otherwise.
- An effect body may `return fn() { … }` to register a cleanup function of type `fn(): Unit`; every other returned value is discarded.
- Effects run after the run completes, never contribute children, and `await` is not allowed in an effect body (`E0706`).

## Two-Way Binding `$`

```js
Input(value: $name)          // passes a binding, not a copy
Checkbox(checked: $isActive)
```

- `$name` is legal **only in an argument position of a component invocation** (`E0703` elsewhere), and the name must be an `@State` binding or a `@Store` binding of the enclosing component (`E0711` for a plain function, `E0712` for an ordinary `let`).
- It is not an expression: it cannot be stored, passed to a function, or used as a value.
- The receiver gets the current value plus a write-back channel; writing through it updates the source and schedules the source component to re-run.

## Where State Declarations Are Legal

| Location | `@State` / `@Store` / `@Environment` / `@Effect` |
|----------|----------------|
| Top level of `fn …(): View` | allowed |
| Plain function, `async` function | error (`E0701`) |
| Nested block, loop body inside a component | error (`E0701`) |

```js
fn helper() {
  @State let count = 0        // error: not a component body
}

fn Panel(): View {
  if true {
    @State let hidden = false // error: nested block
  }
  Text("panel")
}
```

Two state declarations with the same name in one component body are an error (`E0103`) — `@State`, `@Store`, and `@Environment` draw from one name pool per body.
