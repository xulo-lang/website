---
title: Variables & State
description: Variable bindings, reactive state, and effects in XULO.
---

XULO has two kinds of bindings: plain variables (`let` / `let mut`) and reactive state (`@State` / `@Store` / `@Environment` / `@Effect`).

## Variable Bindings

```js
let count = 0                 // Immutable by default
let mut x = 10                // Explicitly mutable
let name: string = "Alice"    // With type annotation
let maybe: string? = null     // Optional type
```

**Rules:**

- `let` = immutable binding by default
- `let mut` = explicitly mutable binding
- Type annotation comes after the name, separated by `:`
- Types can be inferred; annotations are optional
- Assignment `x = x + 1` requires `let mut`; assigning to `let` is an error

### Mutability Comparison

| Syntax | Mutable | Use case |
|--------|---------|----------|
| `let x = 1` | No | Local values that won't change |
| `let mut x = 1` | Yes | Values that will be reassigned |

## Local State `@State`

```js
@State let count: number = 0
@State let name: string = ""
@State let isActive: boolean = true
```

- `@State` can only be declared at the top level of a UI component (a function returning `View`)
- Triggers UI re-render
- Compiles to a reactive signal: read via `.get()`, write via `.set()`

## Global State `@Store`

### Defining a Store

```js
// stores/app.xulo
import { createStore } from "@xulo/store"

type AppState = {
  user: User?
  theme: Theme
  notifications: list<string>
  loading: boolean
}

fn setUser(state: AppState, user: User?): AppState {
  ({ ...state, user: user })
}

fn setTheme(state: AppState, theme: Theme): AppState {
  ({ ...state, theme: theme })
}

pub fn useAppStore() = createStore(
  {
    user: null,
    theme: Theme.Light,
    notifications: [],
    loading: false
  },
  {
    setUser: setUser,
    setTheme: setTheme
  }
)
```

### Using a Store

```js
import { useAppStore } from "../stores/app"

fn Home(): View {
  @Store let { user, theme, loading } = useAppStore()
  @Store let { setTheme } = useAppStore()

  VStack {
    Text("User: " + user?.name)
    Button(onClick: () => setTheme(Theme.Dark)) {
      Text("Dark mode")
    }
  }
}
```

- `@Store` destructures values (`{ user }`) and functions (`{ setUser }`)
- Dependency tracking and re-rendering are handled by the external store runtime

## Environment Injection `@Environment`

```js
@Environment let router: Router
router.push("/about")
```

- Injects a value from the external runtime (compiles to `__env("Router")`)
- Only available at the top level of `View` component functions

## Side Effects `@Effect`

```js
@Effect () => {
  // Runs when component mounts
  fetchUser(id)
}

@Effect () => {
  // Re-runs when dependencies change
  fetchUser(id)
}, [id]

@Effect () => {
  // Cleanup function
  setupSubscription()
  return () => {
    cleanupSubscription()
  }
}
```

- `@Effect` runs when the component mounts
- Supports dependency array `[id]`
- Supports returning a cleanup function

## Two-Way Binding `$`

```js
// Two-way binding (use $ prefix)
Input(value: $name)
Checkbox(checked: $isActive)

// Equivalent to
Input(value: name, onInput: (e) => {
  name = e.value
})
```

- `$` prefix enables two-way binding
- Only works with `@State` or `@Store` variables
- Compiles to `{ value, onChange }`

## Usage Restrictions

`@State`, `@Store`, `@Effect`, and `@Environment` can **only** be used at the top level of functions whose return type is `View`.

### Correct (inside UI components)

```js
fn UserProfile(): View {
  @Store let { user, loading } = useAppStore()
  @State let editing: boolean = false
  @Effect () => { fetchUser(id) }

  VStack { ... }
}
```

### Incorrect (in plain functions / async functions / nested blocks)

```js
fn helperFunction() {
  @Store let { user } = useAppStore()  // Error
  @State let count = 0                 // Error
}

fn main(): View {
  if true {
    @State let x = 0                     // Error (nested block)
  }
}
```

| Syntax | Allowed | Prohibited |
|--------|---------|------------|
| `@State` | Top level of `fn ...(): View` only | Plain functions, async functions, nested blocks |
| `@Store` | Top level of `fn ...(): View` only | Plain functions, async functions, nested blocks |
| `@Effect` | Top level of `fn ...(): View` only | Plain functions, async functions, nested blocks |
| `@Environment` | Top level of `fn ...(): View` only | Plain functions, async functions, nested blocks |
