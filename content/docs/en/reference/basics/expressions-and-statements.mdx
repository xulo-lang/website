title: Expressions & Statements
description: Operators, precedence, and the statement rules in XULO.

XULO is expression-oriented but not purely so: a small set of constructs is a statement and produces no value.

## Statement / Expression Split

| Construct | Category |
|-----------|----------|
| `let`, `let mut`, `const`, destructuring bindings | statement |
| `place = value` | statement |
| `return e`, `return` | statement |
| `break`, `continue` | statement |
| `defer e`, `defer { … }` | statement |
| `for … in … { … }`, `while … { … }` | statement |
| bare expression in statement position | statement |
| `if` / `else`, `match`, block `{ … }` | expression |
| literals, operators, member access, subscript, calls | expression |
| closures, `await`, `?` propagation, `panic(...)` | expression |

**Statement termination.** The grammar is newline-insensitive: a statement ends when the next token cannot continue it, and `;` is an optional terminator — this is not automatic semicolon insertion. Several statements on one line are separated with `;`.

**The statement-value rule.** An expression statement that is not `Unit` is an error (`E0218`), **except** when it is a control-flow construct (`if`, `match`, `for`, `while`) whose value is discarded, or a `Task` returned by `send` on a service handle — a fire-and-forget message whose reply goes unread.

```js
print("hi")                              // legal: Unit call
total + 1                                // error: value discarded (E0218)
if total > 0 { print("yes") }            // legal: control-flow exception
total > 0 ? a() : b()                    // error: ternary is not control flow
worker.send(cmd)                         // legal: a service send's Task may be discarded
let sum = a + b                          // legal: expression position uses the value
```

Two structural restrictions follow the same rule:

- An expression statement must not begin with `{` — statement-position `{` always starts a block. Parenthesize a map literal: `({ a: 1 })`.
- The trailing expression of a block is its value; writing `;` after it discards that value (`42;` in an `Int` function is `E0218`).

## Operator Precedence

Levels from loosest to tightest binding:

| Level | Operators | Assoc |
|-------|-----------|-------|
| assignment | `=` | right |
| ternary | `?:` | right |
| logical or | `or` | left |
| logical and | `and` | left |
| nullish | `??` | left |
| equality | `==` `!=` | left |
| type test | `is` `is not` | non-assoc |
| relational | `<` `>` `<=` `>=` | non-assoc |
| range | `..<` `...` | non-assoc |
| bitwise or | `\|` | left |
| bitwise xor | `^` | left |
| bitwise and | `&` | left |
| shift | `<<` `>>` | left |
| additive | `+` `-` | left |
| multiplicative | `*` `/` `%` | left |
| power | `**` | right |
| unary | `!` `-` `~` `await` `move` `copy` | prefix |
| postfix | `f(x)` `x[i]` `x.y` `x.0` `x?.y` `x?.0` `x?` | left |

Non-assoc operators must not be chained: `a < b < c` does not parse — write `a < b and b < c`. Prefix `...` (spread) exists only inside list and map literals and is not part of this chain.

## Assignment

```js
let mut x = 1
x = x + 1
a = b = c            // right-associative: a = (b = c), each yielding Unit
```

The target must be a place backed by a `mut` binding (`E0401`); the right-hand side is evaluated before the write; the result is `Unit`. **Compound assignment does not exist** — no `+=`, `-=`, `*=`, or increment operators.

## Logical and Ternary

```js
let ok = a > 1 and b < 2        // `and` / `or`, not && and ||
let grade = score >= 90 ? "A" : "B"
print(!flag)
```

- `and`, `or`, and `!` take and yield `Boolean` only; there is no truthiness (`E0201`). `and` and `or` short-circuit.
- The ternary condition must be `Boolean`; both branches must have a common type. It is right-associative and is **not** a control-flow construct, so in statement position its type must be `Unit`.
- The `?` of a ternary is read first whenever `Expression :` follows it, so `c ? a : b` and `f()?` are each read as written.

## Equality and Type Tests

```js
let same = [1, 2] == [1, 2]
let ok = data is String
if size is not Int { print("other") }
```

- Equality is structural for primitives, `List`, `Map`, `Set`, tuples, structs, and enums; both operands must have a common type (`E0211`), so there is no cross-type equality.
- `null == null` is `true`; comparing `null` with a value requires that value's type to be optional.
- `is` / `is not` yield `Boolean` and are non-associative. The right side must be a **testable type** — a base type, a non-generic struct/enum, `Unknown`, or a union/optional of testable types (`E0222`).
- As the condition of an `if`, `x is T` narrows `x` in the branches; in every other `Boolean` position it is an ordinary test.

## Arithmetic, Bitwise, Shift

```js
let sum = a + b
let square = n ** 2            // right-associative
let half = -x                  // unary binds tighter than any binary operator
let bits = flags & mask
let wide = n << 2
```

- Integer division truncates toward zero (`-7 / 2` is `-3`); `%` takes the sign of the dividend (`-7 % 2` is `-1`).
- Mixed `Int`/`Float` promotes to `Float`; fixed-bit types stay in their own type, and other mixtures are errors (`E0201`). Constant overflow is `E0210`, a literal out of range is `E0209`.
- Division or remainder by zero is a compile-time error on constants (`E0210`) and a runtime trap otherwise.
- Bitwise and shift operators take integers of the same type; `<<`/`>>` bind tighter than `&`, so `a < b | c` groups as `a < (b | c)`.

## String and List `+`

```js
print("Hello, " + who + "!")
print("count=" + str(count))
let all = head + tail
```

`String + String` yields `String`; `List<T> + List<U>` yields `List<T | U>`. Mixing a string with a non-string is an error (`E0227`) — convert explicitly with `str(x)` or a template. There is no implicit conversion anywhere.

## Access, Optional Chaining, Spread

```js
user.name                // member access (struct field, map key, method)
xs[0]                    // subscript
p.0                      // tuple position
user?.name               // optional member access
session?.refresh()       // null receiver short-circuits the whole chain
let name = user?.name ?? "anonymous"
let all = [...head, ...tail]
let merged = { ...base, active: true }
```

- `?.` is the only optional-chaining form — there is no optional subscript. Each `?.` step adds one optional layer, and when the receiver is `null` the rest of the chain (including call arguments) is not evaluated.
- `??` requires an optional left operand: `T? ?? T` is `T`, `T? ?? U` is `T | U`. It reacts only to `null`, never to `false`, `0`, or `""`.
- Prefix `...` appears only inside list and map literals, with a `List` operand in a list and a `Map` operand in a map; a later duplicate key wins.

## Calls

```js
double(21)
xs[0](10)        // a function in a list
getFn()(x)       // a returned function
(f)(5)           // parenthesized callee
```

The callee is evaluated first, then arguments left to right, each exactly once. A call through a function **value** (`fn(…)`) accepts positional arguments only — named arguments exist for declared functions and methods. Calling a non-function is `E0204`.

## Blocks as Values

```js
let x = {
  let a = 1
  let b = 2
  a + b          // the block's value
}
```

A block's type is its final expression's type, or `Unit` when there is none. The final expression must not be followed by `;` if its value is wanted.

## `defer`

```js
fn handle(path: String) {
  let f = open(path)
  defer close(f)          // runs when this block exits
  process(f)
}
```

- `defer e` (or `defer { … }`) **registers** the operand; it is evaluated when control leaves the enclosing block, and its value is discarded. Several defers in one block run in reverse order of registration.
- Control leaves a block at its end, on `return`, the early return of `?`, `break`/`continue` out of it, and when the task stops as cancelled at an `await`. `panic` runs no defers.
- `return`, `break`, `continue`, and `?` must not appear in a defer operand (`E0229`).
- A block's defers run after its value is determined and after the tasks spawned in the block have settled, so cleanup can no longer change the result. Use `defer` (or cleanup written on each path) instead of a destructor: the language has none.

## Evaluation Order

| Construct | Evaluated | Skipped |
|-----------|-----------|---------|
| `A and B` / `A or B` | `A` first | the right operand when short-circuited |
| `c ? x : y` | `c`, then one branch | the other branch |
| `a ?? b` | `a`; `b` only when `a` is `null` | `b` otherwise |
| `if c { A } else { B }` | `c` once, then the selected branch | the other branch |
| `match e { … }` | `e` once, then each pattern, its guard, then the body | every later arm |
| `for x in it { B }` | `it` once, then one binding and `B` per element | the body when empty |
| `while c { B }` | `c` before each iteration | the body when `c` is false |

Statements in a block are evaluated in source order with no reordering across statement boundaries.
