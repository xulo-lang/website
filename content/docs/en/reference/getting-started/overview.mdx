Xulo is a UI-first, statically typed language: a single `.xulo` file carries both the logic of a program and the interface it presents. Types are checked before the program runs, local type inference covers the interior of function bodies, and there is one syntax for logic and layout.

## Two Modes

XULO programs come in two forms, decided by the signature of the entry point:

**Terminal** — plain logic, no UI:

```js
fn main() {
  let name = "World"
  println(`Hello, ${name}`)
}
```

**UI** — return `View` to render a component tree:

```js
fn main(): View {
  Screen {
    Center {
      Text("Hello, XULO!")
    }
  }
}
```

A plain `fn main()` runs **headlessly**: the body executes and nothing is painted. `fn main(): View` is a **renderable program** — the host invokes `main`, lays out and paints the tree it returns, and invokes it again for every later pass.

## Core Syntax

### Functions

```js
fn add(a: Int, b: Int): Int {
  a + b
}
```

Use `fn` to declare functions. Parameters are typed with `:`; every parameter type is annotated. The trailing expression is the implicit return value — no `return` needed.

### Variables

```js
let x = 10               // Immutable by default
let mut y = 20           // Assignable
const PI = 3.14          // Compile-time constant
let name: String = "Alice"
```

`let` introduces an **immutable** binding — assigning to it is an error. `let mut` opts into mutation, `const` names a compile-time constant, and a type annotation, when present, follows the name separated by `:`.

### Structs & Enums

```js
struct Point { x: Int, y: Int }

enum Direction {
  Up
  Down
  Left
  Right
}
```

`Point(x: 0, y: 0)` constructs a struct value. `Direction::Up` names a variant — `::` walks the declaration lane (packages, modules, variants, associated names — `Math::max`, `Theme::Dark`, `form::validate`), while `.` reaches into a value only (fields, methods, map entries).

### Control Flow

```js
if x > 0 {
  println("positive")
} else {
  println("non-positive")
}

for i in 0..<10 {
  println(str(i))
}

match direction {
  Direction::Up => move_up()
  _ => {}
}
```

- `if` and `match` are expressions: an `if` with an `else` and a `match` take the common type of their branches/arms.
- Conditions must have type `Boolean` — there is no truthiness.
- `0..<10` is a half-open range, `0...10` is closed; `for` also iterates `List`, `Map` (its keys), and `Set`.
- A `match` must account for every case of the value it destructures.

## UI Components

A **component** is a function whose declared return type is `View` — that return type, never the spelling of the name, marks it as one:

```js
fn Dashboard(): View {
  Screen {
    Header {
      Text("Dashboard")
    }
    Body {
      VStack(spacing: 16) {
        Card(title: "Stats", radius: "lg") {
          Text("3,214 accounts")
        }
        Button("View All", variant: "outline")
      }
    }
  }
}
```

- Components are conventionally UpperCamelCase; attributes are `key: value` pairs in `( )`.
- Structure comes from `{ … }` blocks: no closing tags, no angle brackets.
- A block's children are component invocations, strings, `if`, `for`, and expressions of type `View` or `List<View>` — never declarations or assignments.
- `@State`, `@Store`, `@Effect`, and `@Environment` appear at the top level of a component body and give it memory, work, and access to its surroundings.

## Values

- **String** — `"..."` or `'...'`; only a template literal in backticks interpolates
- **Number** — `Int` (`400`), `Float` (`1.5`); conversions are explicit with `str(x)`, because `+` never mixes strings and numbers
- **Boolean** — `true` / `false`

## Comments

`//` starts a line comment, up to the end of the line; `/* … */` is a block comment. Comments carry no meaning to the language.

```js
// This is a comment
println("Hello")
```
