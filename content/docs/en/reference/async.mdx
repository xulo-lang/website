## `async` / `await`

```js
async fn fetchUser(id: string) {
  let response = await fetch("/api/users/" + id)
  let data = await response.json()
  return data
}
```

- `async` prefix declares an async function (equivalent to JS `async function`)
- `await` can only appear inside async functions; using `await` on a non-Promise value is an error
- `throw <expr>` throws an exception

## `try` / `catch`

```js
async fn fetchUser(id: string) {
  try {
    let response = await fetch("/api/users/" + id)
    return await response.json()
  } catch (e) {
    print("Error: " + e.message)
    return null
  }
}
```

## Async Closures

```js
async fn main() {
  let work = async fn() { 21 * 2 }
  print(await work())   // 42
}
```

Async closures are written as `async fn()`, return a Promise when called, and can be `await`ed.

## State Restrictions in Async Functions

Async functions **cannot** use `@State`, `@Store`, `@Effect`, or `@Environment`. Use **direct Store API calls** instead:

```js
// Correct: call useAppStore() directly
pub async fn fetchUser(id: string) {
  let store = useAppStore()
  store.actions.setLoading(true)
  let data = await fetch("/api/users/" + id).json()
  store.actions.setUser(data)
}

// Incorrect: using @Store in an async function
pub async fn fetchUser(id: string) {
  @Store let { setUser } = useAppStore()  // Error
}
```
