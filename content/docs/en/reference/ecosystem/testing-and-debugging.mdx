## Overview

Tests live in the same source files as the code they check. The language contributes exactly two things to testing — the `test fn` form and the `assert` intrinsic — so that a test is checked with the rest of the program and discoverable from the source itself. Everything else — which tests a tool discovers, the order it runs them, what each run is isolated from, and how a failure is reported — belongs to the tool, not to the language. There is no test framework to learn and no assertion library to install.

## Test functions

A test is a function marked with `test`. It appears at file scope, among a module's top-level declarations:

```js
test fn map_get_answers_null() {
  let m = { a: 1 }
  assert(map_get(m, "z") == null, "absent key is null")
}
```

A test function has a fixed shape — the marker adds nothing optional beyond `async`:

| Slot | Rule |
|------|------|
| parameters | none: the list is empty |
| return type | none: the body is an implicit `fn(): Unit` |
| `pub` | none: a test is never part of an interface |
| generics / `where` | none |

- **Always checked.** The body is checked exactly as a `fn(): Unit` body is checked — types, exhaustiveness, mutability, the statement-value rule — whether or not any tool ever runs it. A file whose tests do not check is rejected like any other file.
- **The name binds no value.** The identifier is the test's identity as tools report it, not a callable name: any reference to it — a call, a value use, a path — is a compile-time error (`E0107`). A check that would recurse is written as an ordinary helper function that the test calls.
- **Inert.** No execution of the program evaluates a test body: the name binds no value, so nothing can reach it. Statements in a test body run only under a tool.

```js
test fn reference_is_forbidden() {
  assert(true, "runs only under a tool")
}

fn main() {
  reference_is_forbidden() // error: `reference_is_forbidden` is a test function and cannot be referenced (E0107)
}
```

## Async tests

A test whose body suspends is marked `async`; the marker follows `test` (`test async fn`, never `async test fn`):

```js
test async fn delayed_task_finishes() {
  await Time.sleep(1) // ok: an async test body is an async context
}

test fn await_needs_the_async_marker() {
  await Time.sleep(1) // error: `await` outside of an `async` context (E0501)
}
```

With the marker the body is an `async` context exactly as an `async fn(): Unit` body is; without it, `await` is `E0501`. When a tool runs the test, the body starts as its own task.

## Pass and fail

A test passes or fails by one criterion:

| Outcome | Condition |
|---------|-----------|
| **pass** | the body runs to completion — for an `async` test, when the task its body started settles as completed |
| **fail** | a `panic` or a runtime failure stops the body, or — for an `async` test — that task settles as cancelled |

`panic` behaves inside a test body as it does anywhere else: it stops the execution that reached it — here, the running of that test ([Error Handling](/en/docs/reference/stdlib/error-handling/)). Which tests execute, in what order, each in what isolation, and whether a run continues after a failure are the tool's to decide.

## `assert`

| Signature | Result |
|-----------|--------|
| `assert(condition: Boolean, message: String): Unit` | `Unit` |

- Arguments are checked and evaluated left to right like any other call: `message` is evaluated whether or not `condition` holds.
- When `condition` is `false`, the call stops the program with `panic(message)` — the same effect as writing that `panic` directly.
- When `condition` is `true`, the call has no effect beyond producing `Unit`.

```js
let xs = [2, 4, 6]
assert(list_size(xs) == 3, "three items") // ok: no effect
assert(list_size(xs) == 4, "not four")    // false: stops with panic("not four")
```

`assert` is an intrinsic, like `print`, `println`, and `str`: available without import, exactly one signature, and the name is reserved — a module-scope declaration MUST NOT bear it (`E0106`).

See also: [Testing (spec)](/en/docs/spec/testing/), [Intrinsic Functions (spec)](/en/docs/spec/builtins/intrinsic-functions/), and [Error Handling](/en/docs/reference/stdlib/error-handling/) for `panic`.
