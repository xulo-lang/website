## Overview

JSON is a standard-library API, not a language built-in. The specification places JSON (with regular expressions and I/O) outside the language: nothing named `JSON` is part of the prelude or of the intrinsics, so a module that imports nothing has no `JSON` in scope. Import the module as a namespace:

```js
import * as JSON from "std/json"        // the namespace: JSON.stringify, JSON.parse
import { JSONError } from "std/json"    // the error type, where an annotation names it
```

Parsing never throws. `JSON.parse` returns a `Result<T, JSONError>`, which the caller inspects with `match` or propagates with `?`. The type argument `T` is inferred at the call site from the expected type — there is no `JSON.parse<User>(…)` form: explicit type arguments at a call site are not part of the language.

## Methods

### `JSON.stringify<T>(value: T): String`

Serializes a value into a JSON string.

```js
let data = { name: "Alice", age: 30, active: true }
let json_str = JSON.stringify(data)
// '{"name":"Alice","age":30,"active":true}'

let list = [1, 2, 3]
let json_list = JSON.stringify(list)
// '[1,2,3]'
```

### `JSON.parse<T>(input: String): Result<T, JSONError>`

Deserializes a JSON string. `T` is inferred from the expected type: annotate the binding, or let the enclosing function's declared return type supply it.

```js
let raw = '{"name":"Alice","age":30}'

// T from the annotation on the binding
let outcome: Result<User, JSONError> = JSON.parse(raw)

// T from the declared return type
fn load_user(raw: String): Result<User, JSONError> {
  JSON.parse(raw)
}
```

### `JSON.parse_async<T>(input: String): Task<Result<T, JSONError>>`

Async variant of `parse`. The call yields a `Task`; `await` it to reach the `Result`. Combine `await` and `?` with parentheses: `(await …)?`.

```js
async fn load_user_async(raw: String): Result<User, JSONError> {
  let user: User = (await JSON.parse_async(raw))?
  Result::Ok(user)
}
```

## Error Handling

Failures are values. There is no `throw` and no `try` / `catch`: a malformed document arrives as `Result::Err(JSONError)`.

`JSONError` is the JSON module's own error enum — a domain failure carried in the `E` slot, exactly as a program's own enums are:

| Variant | Meaning |
|---------|---------|
| `JSONError::SyntaxError(msg, line, col)` | the document is not well-formed JSON |
| `JSONError::TypeMismatch(expected, actual)` | a value does not fit the requested type |
| `JSONError::UnexpectedEof` | the input ended unexpectedly |

```js
let outcome: Result<User, JSONError> = JSON.parse(raw)

match outcome {
  Result::Ok(user) => print("Welcome, " + user.name)
  Result::Err(reason) => match reason {
    JSONError::SyntaxError(msg, line, col) => print(`JSON error at ${line}:${col}: ${msg}`)
    JSONError::TypeMismatch(expected, actual) => print("expected " + expected + ", got " + actual)
    JSONError::UnexpectedEof => print("input ended unexpectedly")
  }
}
```

Inside a function that already returns a `Result`, propagate instead of matching:

```js
fn user_name(raw: String): Result<String, JSONError> {
  let user: User = JSON.parse(raw)?
  Result::Ok(user.name)
}
```

## Use Cases

- **Data Exchange**: serialize and deserialize data when communicating with external APIs
- **Persistence**: save values as JSON files
- **Configuration Parsing**: read JSON-format configuration files
- **Debugging**: render values as readable strings

## Examples

```js
import * as JSON from "std/json"
import { JSONError } from "std/json"
import { File } from "std/fs"

// Serialize
fn save_user(user: User) {
  let json_str = JSON.stringify(user)
  File.write("user.json", json_str)
}

// Deserialize: the Err case travels up untouched
fn load_user(raw: String): Result<User, JSONError> {
  JSON.parse(raw)
}

// Interact with an HTTP API: propagate with `?`
fn fetch_data(raw: String): Result<ApiResponse, JSONError> {
  let data: ApiResponse = JSON.parse(raw)?
  Result::Ok(data)
}
```

## Design Notes

- **Errors are data.** `JSON.parse` returns `Result<T, JSONError>`; Xulo has no exceptions, so nothing is thrown and nothing is caught ([Error Handling](/en/docs/spec/error-handling/)).
- **`JSONError` is a library enum.** The only built-in error type is `Error` — constructed as `Error("…")`, carrying one `message: String` field, with no subtypes and no inheritance. `Result<T, Error>` is the conventional shape for system-level failures; a failure with structure is an ordinary enum.
- **Type arguments are inferred.** `parse<T>` is written `T` in the signature only; at the call site the expected type supplies it (`let outcome: Result<User, JSONError> = JSON.parse(raw)`).
- **Import required.** `JSON` is neither a prelude name nor an intrinsic; see [Prelude](/en/docs/spec/builtins/prelude/) and the specification's [scope statement](/en/docs/spec/introduction/).
- Further reading: [Error Handling](/en/docs/spec/error-handling/), [Calls](/en/docs/spec/expressions/calls/), [Standard Library](/en/docs/reference/stdlib/standard-library-net-fs/).
