## Overview

JSON is a standard-library API, not a language built-in: nothing named `JSON` or `Json` is part of the prelude or the intrinsics. The module is `std::json`, and its qualified path needs no import:

```js
std::json::parse("[1, 2, 3]")       // Result<any, Error>
std::json::stringify({ a: 1 })      // Result<string, Error>
std::json::valid("{}")              // bool
```

The six `use` forms bind it like any other module — `use std::json;` then `json::parse(…)`, `use std::json as JSON;`, or `use std::json::{parse, stringify, valid};`. A bare `json::parse(…)` head and a capital `Json::parse(…)` are `E0607`.

The module has exactly three functions and no types of its own. Failures are values: `parse` and `stringify` return `Result<_, Error>`, while `valid` is total. No `std::json` member stops the program on the program's own inputs.

## The Value Model

`parse` maps JSON onto runtime values, and `stringify` maps them back:

| JSON | Runtime value |
|------|---------------|
| `null` | `null` |
| `true` / `false` | a `bool` |
| `string` | a `string` |
| `number` | a `number` — binary64 |
| `array` | a `list`, elements in order |
| `object` | an `object` with the same members |

- **Numbers are binary64.** A value within ±2⁵³ round-trips exactly; beyond that a parse-then-stringify round trip may change the decimal representation. JSON has no spelling for `NaN` or the infinities: such a document is a syntax error, and those values only arise from computation.
- **Object members are ordered by UTF-8 byte order in both directions.** `parse` builds members in that order, so the input document's key order is not preserved; duplicate keys keep the last occurrence. `stringify` emits members in the same sorted order.
- **Nesting is bounded.** Both directions share one ceiling of 128 levels; a deeper document or value is `Err`, never a partial result and never a trap.
- **Lists and tuples are arrays.** A list serializes in order; a tuple serializes as the array of its elements. `parse` reads an array as a `list`, so a tuple's type is not carried by the text.
- **Maps are objects.** A `Map<string, V>` and an object literal emit their entries as members under the sorted-members rule. Keys of other types are textified on the way out: an `int` by its decimal form, a finite `float` by its JSON number form (`1.0` keys as `1`), a `bool` as `true` or `false`. Two keys that textify to the same string, a non-finite `float` key, and an enum key are `Err`. Textified keys come back as `string` keys from `parse`.
- **Sets are arrays in a defined order.** `stringify` emits the elements sorted by their compact JSON text in UTF-8 byte order; `parse` reads a `list`, and `Set::fromList` restores the set.

```js
std::json::stringify(Set::fromList(["b", "a"]))   // ["a","b"]
std::json::stringify(Map<int, string>{ 1: "x" }) // {"1":"x"}
std::json::stringify((1, "x"))                   // [1,"x"]
```

## Parsing

### `std::json::parse(text: string): Result<any, Error>`

Reads the single JSON value `text` describes. The success value is typed `any`: the checker does not look inside, and member access, indexing, and arithmetic on it are the program's business.

- Leading and trailing whitespace around the value are fine; any other trailing content is `Err`, as are the empty string and whitespace-only text.
- `Err` classes: a syntax error (with a position in the informative message), unexpected end of input, trailing content, a number outside binary64 range (`1e400`), and nesting past the depth ceiling.
- There is no size limit beyond the depth ceiling.
- `parse` never uses `null` as a stand-in for failure: a `null` it yields is JSON's `null`, inside `Ok`.

```js
match std::json::parse("{\"b\": 2, \"a\": 1}") {
  Result::Ok(v) => print(v.a)          // 1 — `any` admits the member access
  Result::Err(e) => print(e.message)
}
```

## Stringifying

### `std::json::stringify(value: any, indent: number? = null): Result<string, Error>`

Writes `value` as JSON text — compact by default, or indented when `indent` is given.

- The default — `indent` omitted, `null`, or `0` — is one compact line with only `,` and `:` as separators: `{"a":[1,"two"],"b":2.5}`.
- `indent` in **`1 …= 8`** produces one line per array/object, each level indented `indent` spaces, `: ` after a key, and `\n` between items; an empty object or array stays `{}` or `[]`. The text ends with the value: no trailing newline.
- The `indent` domain is **`0 …= 8`**; a fractional value truncates toward zero. A value outside the domain — negative, above 8, non-finite — is `Err`, checked before the value is walked.
- Members are emitted sorted by UTF-8 byte order, so indentation never disturbs determinism.
- Numbers print without a needless fractional part: `2.0` prints `2`, negative zero prints `0`, and other values print in the shortest decimal form that restores the same binary64 (scientific notation is allowed for very large magnitudes).
- Text escapes only what JSON requires (`\"`, `\\`, `\n`, `\r`, `\t`, `\b`, `\f`, `\u00XX` for other controls); other non-ASCII text is emitted as raw UTF-8.
- `Err` classes: an `indent` outside the domain; `NaN` or an infinity at any depth; values JSON cannot represent (functions, enum values, `Ptr`, signals, promises); map keys that do not textify distinctly; cycles; and nesting past the depth ceiling.

```js
match std::json::stringify({ name: "x", n: 3 }) {
  Result::Ok(text) => print(text)       // {"n":3,"name":"x"}
  Result::Err(e) => print(e.message)
}

std::json::stringify({ name: "x" }, 2)
// {
//   "name": "x"
// }

std::json::stringify(std::math::NAN)
// Result::Err: cannot serialize NaN as JSON
```

## Validating

### `std::json::valid(text: string): bool`

Whether `text` is a well-formed JSON document.

- Total for every `string`: `true` or `false`, never a `Result`, `null`, or a runtime failure.
- `valid(text)` is `true` exactly when `parse(text)` yields `Ok` — one grammar, one depth ceiling, one binary64 range, and the same trailing-content rule.

```js
std::json::valid("{\"a\": 1}")    // true
std::json::valid("{\"a\": }")     // false
std::json::valid("")              // false
```

## Structs

A struct value is an ordinary member set for `stringify`: **every field the value carries becomes a member of the JSON object, private fields included.** `pub` is a compile-time name rule, not part of a value, so it cannot hide a field from serialization.

```js
struct User { name: string, age: int, passwordHash: string }

let alice = User(name: "Alice", age: 30, passwordHash: "5e88…")
std::json::stringify(alice)
// {"age":30,"name":"Alice","passwordHash":"5e88…"} — every field
```

To choose the members, hand over an object literal or implement an inherent `toJson` returning the value to serialize:

```js
impl User {
  pub fn toJson(self): any { ({ name: self.name, age: self.age }) }
}

std::json::stringify(alice.toJson())     // the chosen members only
```

`stringify` never calls `toJson` itself: the program calls it. On the way back, `parse` yields the plain object the document describes — never a struct — and the constructor restores the type: `User(name: v.name, age: v.age)`.

## Error Handling

Both failures are ordinary `Result::Err` values carrying the built-in `Error { message }`; the module introduces no error type of its own. A `parse` failure is about the text; a `stringify` failure is about the value. Message text is informative.

```js
fn load_user(raw: string): Result<User, Error> {
  let v = std::json::parse(raw)?
  Result::Ok(User(name: v.name, age: v.age))
}

fn save_user(user: User): Result<string, Error> {
  std::json::stringify(user)
}
```

- **No exceptions.** There is no `throw` and no `try` / `catch`; propagate with `?` in a function returning `Result<_, Error>`, or inspect with `match`.
- **No type arguments.** No `std` member takes a type parameter in version 0.1, so `std::json::parse<int>(…)` is `E0807`.
- **`use` or `std::` required.** `std::json` is neither a prelude name nor an intrinsic; a bare `json::parse` or `Json::parse` is `E0607`.
- Further reading: [Error Handling](/en/docs/spec/error-handling/), [Calls](/en/docs/spec/expressions/calls/), [Standard Library](/en/docs/reference/stdlib/standard-library-net-fs/), and the [standard-library specification](https://github.com/xulo-lang/std-spec).
