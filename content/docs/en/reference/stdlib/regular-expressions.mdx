## Overview

Regular expressions are a standard-library API in `std::regex`. The grammar has no `/pattern/flags` literal: in expression position `/` is division, and patterns are ordinary `string` values. `std::regex` exports **three types and no values** — `RegExp`, `RegexError`, and `RegexMatch` — so `RegExp::compile(…)` is reached through the imported type name, not through a module namespace:

```js
use std::regex::{RegExp, RegexError};   // the canonical form
use std::regex::RegExp;                 // one type under its own name
use std::regex::*;                      // RegExp, RegexError, RegexMatch
```

`use std::regex;` and `use std::regex as R;` are `E0607` — there is no value namespace to bind. The three type names also resolve in annotation position without an import, while expressions that name them need the binding.

Compiling never throws: `RegExp::compile` returns `Result<RegExp, RegexError>`, so an illegal pattern or flag is a value the caller handles with `match` or `?`.

## Compiling

### `RegExp::compile(pattern: string, flags: string? = null): Result<RegExp, RegexError>`

Compiles a pattern string with optional flags. Zero or three arguments are `E0207`, a non-`string` argument is `E0202`, and named arguments are rejected.

Failure — an unknown flag or a pattern the engine cannot parse — is `Result::Err(RegexError)`, never a panic and never the built-in `Error`. Success carries an immutable `RegExp` that every matching member reads.

```js
match RegExp::compile("[a-z]+", "i") {
  Result::Ok(re) => print(re.test("ABC123"))   // true
  Result::Err(e) => print(e.message)
}
```

### Flags

| Flag | Effect |
|------|--------|
| `i` | case-insensitive matching, by Unicode case folding |
| `m` | multi-line: `^` and `$` also match at line edges |
| `g` | remembered by the pattern: `string.replace` substitutes every match instead of the first |
| `u` | accepted and a no-op — Unicode matching is the engine's default and only mode |
| `s` | dotall: `.` also matches a newline |

The flag string is scanned left to right; the first character outside `i g m u s` fails compilation with ``unknown flag `x` ``. The omitted or empty flags string means no flags. `g` changes nothing for `test`, `find`, or `findAll`.

### Engine Contract

- Matching is over Unicode scalar values, and `.` matches any scalar except a newline unless `s` is set.
- At the leftmost position where a match exists, the engine prefers the alternative the pattern orders first: `a|ab` finds `a` in `"ab"`.
- Look-around assertions and back-references are **not supported**: `(?=…)`, `(?<=…)`, and `\1` are compile-time failures delivered as `Err(RegexError)`.
- Any other malformed pattern — an unclosed group or class, an unrecognized escape — fails the same way with the engine's parse-error text.

## Matching

| Member | Signature | Meaning |
|--------|-----------|---------|
| `RegExp::test` | `fn(input: string): bool` | whether the pattern matches anywhere in `input` |
| `RegExp::find` | `fn(input: string): RegexMatch?` | the first (leftmost) match, or `null` |
| `RegExp::findAll` | `fn(input: string): List<RegexMatch>` | every non-overlapping match, left to right |

`find` reports absence as `null` — ordinary data, not a failure. `findAll` returns matches in order and non-overlapping, regardless of `g`; an empty match is a match, and the scan always advances, so the list is finite.

```js
match RegExp::compile("(\\d+)-(\\d+)") {
  Result::Ok(re) => {
    let m = re.find("room 42-7")
    if m != null {
      print(`${m.value} ${m.group(1)} ${m.group(2)}`)   // 42-7 42 7
      print(`${m.index} ${m.end}`)                       // 5 9
    }
    for hit in re.findAll("x 42-7 y 8-9") {
      print(hit.value)                                   // 42-7, then 8-9
    }
  }
  Result::Err(e) => print(e.message)
}
```

### `RegexMatch`

| Member | Type | Meaning |
|--------|------|---------|
| `value` | `string` | the matched text |
| `index` | `int` | where the match starts, in Unicode scalar indices |
| `end` | `int` | one past the match's last scalar |
| `group(ref: number \| string)` | `string?` | capture group `ref`, 1-based or by name |

- `index` and `end` count Unicode scalar values, so `input.slice(m.index, m.end)` is exactly `m.value` and `end == index + m.value.len`. An empty match has `index == end`.
- A numeric `group` is **1-based**: `group(1)` is the first parenthesised group. There is no `group(0)` — the whole match is `value` — and an out-of-range index or a group that did not participate returns `null`.
- A string `group` reads a **named** group: `(?P<name>…)` captures like a numbered group, and `group("name")` returns its text. `group("1")` asks for a group named `1`, not index 1. A name no group has returns `null`.

## Substitution

### `string.replace(pattern: RegExp, replacer: string | fn(RegexMatch): string): string`

A method on `string`, not a module function. The receiver is the text, and the argument is a compiled pattern.

- With `g` the substitution covers every match; without it, only the first. A pattern that does not match returns the input unchanged.
- A **string** replacer is a template expanded per match: `$1`… expand capture groups, `$0` expands the whole match, `$name` and `${name}` expand a named group, `$$` is a literal `$`, and a `$` that begins none of these stays literal.
- A **function** replacer receives the `RegexMatch` and returns the replacement text.
- A function replacer that returns a non-string, a replacer that is neither string nor function, and a pattern argument that is not a compiled `RegExp` are runtime failures.

```js
match RegExp::compile("(\\w+)@(\\w+)") {
  Result::Ok(re) => print("ada@example".replace(re, "$2.$1"))   // example.ada
  Result::Err(e) => print(e.message)
}

match RegExp::compile("oo", "g") {
  Result::Ok(re) => print("foo boo".replace(re, fn(m) { "[" + m.value + "]" }))   // f[oo] b[oo]
  Result::Err(e) => print(e.message)
}
```

## Splitting

### `string.split(re: RegExp): List<string>`

A method on `string`, like substitution. The pieces are the text before the first match, between consecutive matches, and after the last, from the same left-to-right non-overlapping scan `findAll` runs, regardless of `g`.

- A match at index 0 gives an empty first piece; a match ending at the end gives an empty last piece.
- A pattern that does not match returns a one-element list holding the input.
- A pattern argument that is not a compiled `RegExp` is a runtime failure.

```js
match RegExp::compile("\\s*,\\s*") {
  Result::Ok(re) => print("a , b,c".split(re))   // [a, b, c]
  Result::Err(e) => print(e.message)
}
```

## Failure Model

| Kind | Members |
|------|---------|
| Fallible (`Result`) | `RegExp::compile` — `Result<RegExp, RegexError>`, the module's own error type |
| Total | `RegExp::test`, `find`, `findAll`; `string.replace` and `string.split` for their declared argument types |
| Absence (`null`) | `find` with no match; `group` at index 0, out of range, not participating, or by an unknown name |
| Runtime failure | `replace`'s function replacer returning a non-string; a replacer that is neither string nor function; a `replace` or `split` pattern argument that is not a compiled `RegExp` |

`RegexError` has the same one-field shape as the built-in `Error` — `{ message: string }` — but it is the module's own type, the one exception to `Result<T, Error>`. Read it as `e.message` in a `Result::Err` arm.

## Design Notes

- **No regex literal.** The grammar defines only integer, float, string, template, boolean, and null literals; `/…/` is not one of them.
- **Optionals, not `!`.** `find` returns `RegexMatch?` and `group` returns `string?`; a null test narrows the binding and `??` supplies a default.
- **Type arguments are rejected.** No `std` member takes a type parameter; `RegExp::compile<int>(…)` is `E0807`.
- Further reading: [Error Handling](/en/docs/spec/error-handling/), [Optional Types](/en/docs/spec/types/composite-types/), [Calls](/en/docs/spec/expressions/calls/), and the [standard-library specification](https://github.com/xulo-lang/std-spec).
