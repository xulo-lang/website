## Overview

`std::io` holds the process's standard streams — stdout, stderr, and stdin — as the real, running operations a program talks to: every write flushes before it returns, and the reads drain stdin. Every member but the two probes is fallible: it returns a `Result`, and a closed or broken stream arrives in the `Err` slot as data, never as a panic. The two terminal probes are total. The module is host-dependent: which bytes the streams carry is the process environment's affair.

The qualified path needs no import:

```js
std::io::print("io: ")                 // stdout, no terminator, flushed
std::io::println("hello stdout")       // a newline appended, flushed
std::io::eprintln("io: hello stderr")  // the same write, on stderr
```

This module has one deviation from the ordinary six `use` forms: the face is eight of the ten exported names — `eprint`, `eprintln`, `flush`, `readLine`, `read`, `readN`, `stdinIsTTY`, `stdoutIsTTY` — and `print` / `println` are withheld from `use` because their local names are prelude intrinsics (`E0601`). The two members behind that rule are reached through the qualified path or a namespace alias, and they are the same flushing writes:

```js
use std::io as io;
io::print("prompt: ")            // exactly std::io::print — flushed before it returns
use std::io::*;                  // binds the face: eprint eprintln flush readLine read readN stdinIsTTY stdoutIsTTY
// `use std::io::print;` and `use std::io as print;` are error[E0601]
```

## Writes

| Member | Signature | Meaning |
|--------|-----------|---------|
| `std::io::print` | `fn(text: string): Result<unit, Error>` | write `text` to stdout with no line terminator |
| `std::io::println` | `fn(text: string): Result<unit, Error>` | write `text` and a `\n` to stdout |
| `std::io::eprint` | `fn(text: string): Result<unit, Error>` | write `text` to stderr with no line terminator |
| `std::io::eprintln` | `fn(text: string): Result<unit, Error>` | write `text` and a `\n` to stderr |

- The text is written as the `string` it is — the bytes of `text` and, for the `println` pair, one `\n` — with no spacing and no rendering of other values; interpolate or `str` a value first.
- **Every write flushes its stream before the call returns.** Output cannot sit in a buffer while the program waits: a prompt written with `print` is visible before a later `readLine()` blocks. The language's bare prelude `print` is a different path with different buffering (the interpreter collects it until the program ends).
- Success is `Ok`; an `Err` means the write or the flush failed — a closed or broken stream, a pipe with no reader. The `message` of the `Error` names the stream and the OS reason; the contract is the `Err` shape and this failure class.

```js
std::io::print("io: ")                 // "io: " on stdout, already flushed
std::io::println("hello stdout")       // "io: hello stdout" + "\n"
std::io::eprintln("io: hello stderr")  // on stderr
```

## Flush

### `std::io::flush(): Result<unit, Error>`

Push anything buffered on stdout to the operating system.

- **`flush` touches stdout only** — not stderr, not stdin.
- Writes through this module flush themselves, so a program that writes only through the four members above never needs it. It exists for completeness and for output the language's own buffering has touched.

```js
match std::io::flush() {
  Result::Ok(_) => null
  Result::Err(e) => {
    std::io::eprintln(e.message)
    null
  }
}
// nothing on success; on a failed flush, the reason on stderr
```

## Terminal Probes

| Member | Signature | Meaning |
|--------|-----------|---------|
| `std::io::stdinIsTTY` | `fn(): bool` | whether stdin is connected to a terminal |
| `std::io::stdoutIsTTY` | `fn(): bool` | whether stdout is connected to a terminal |

- Both probes are **total**: a `bool` for every call — never a `Result`, never `null`. A stream either is a terminal or is not, and the question is always answerable.
- `stdoutIsTTY` is the color guard: a program that writes escape sequences checks it first and writes plain text when the answer is `false`, so output piped to a file or another program stays clean.
- `stdinIsTTY` is the interactivity guard: when it is `false`, input comes from a pipe or a redirect, and a program prompts only when the answer is `true`.
- Stderr is deliberately not probed: no member of this module turns a write on or off by destination — the four writes are unconditional — and the diagnostic stream is written either way.

```js
if std::io::stdoutIsTTY() {
  std::io::println("colored")     // a terminal: escapes are welcome
} else {
  std::io::println("plain")       // piped: keep the bytes clean
}
```

## Text, Not Bytes

- Every reader here decodes **strict UTF-8**: bytes that are not valid text are an `Err`, never a replacement character, and [`readN`](#bounded-reading) stops at a character boundary. Stdin is a text stream in version 0.1 — this module has no byte reader.
- Binary input arrives as a **file**, through [`std::fs::readBytes`](fs.mdx#byte-content); a byte-level surface for the streams (`std::io`, `std::net`) is a roadmap candidate.
- A program handed an object file on stdin never receives mojibake: it fails cleanly at the first invalid byte, and the `message` names the offset. Reading the bytes themselves is `readBytes`, on a path.

## Line Reading

### `std::io::readLine(): Result<string?, Error>`

The next line of stdin without its terminator, or `Ok(null)` at end of input.

- The line is returned through its terminator: a trailing `\n`, or a trailing `\r\n` as the one terminator, is stripped. A final line that ends at end of input with no terminator is still a line, returned whole.
- End of input is **absence**: `Ok(null)` — the `null` inside `string?`, not an `Err`. An empty line is `Ok("")` and never passes for end of input.
- Bytes that are not valid UTF-8 are an `Err`; the `message` names the byte offset at which validity ends.
- The call **blocks** until a line or end of input arrives. There is no size limit: a line of any length is returned whole, or fails only as above.

```js
// stdin holds b"\n" — one empty line, then nothing
std::io::readLine()     // Ok("")
std::io::readLine()     // Ok(null) — end of input, distinct from the line above
```

Reading until end of input is a loop on absence:

```js
let mut done = false
while !done {
  match std::io::readLine() {
    Result::Ok(null) => done = true
    Result::Ok(line) => std::io::println(line)
    Result::Err(e) => {
      std::io::eprintln(e.message)
      done = true
    }
  }
}
```

## Stream Reading

### `std::io::read(): Result<string, Error>`

All of stdin, drained to end of input.

- The remaining stream is returned as one string; the call **blocks** until end of input. There is no size limit.
- End of input with no data is `Ok("")` — not `null`. `read` has no absence case: every success carries a string, empty or not.
- Bytes that are not valid UTF-8 anywhere in the stream are an `Err`, reported exactly as `readLine` reports them — the message names the byte offset.

```js
// stdin is empty
std::io::read()         // Ok("") — no absence; contrast readLine's Ok(null)
```

## Bounded Reading

### `std::io::readN(max: number): Result<string?, Error>`

Up to `max` bytes of stdin, decoded as UTF-8; `Ok(null)` at end of input.

- `max` is a byte count in **`1 …= 16777216`** (16 MiB) — the same domain `std::net::sockRead` names — and a fractional value counts as its truncation toward zero. A value outside that domain is `Err`, checked before the call blocks, so a bad `max` is reported whatever stdin holds.
- The call **blocks** until at least one byte arrives or input ends and yields **up to** `max` bytes of what arrived: a short success is ordinary, and the next `readN` continues the stream where this one stopped. The read stops at a **character boundary** — an incomplete UTF-8 sequence at the cut stays in the stream for the next call, never split and never decoded.
- Decoding is strict: bytes that are not valid UTF-8 are an `Err`, the `message` naming the byte offset — never a replacement character. `std::net::sockRead` decodes lossily because a socket carries arbitrary bytes; stdin is text, as this module's other two readers already assume.
- End of input is **absence**: `Ok(null)`, the same shape as `readLine`. EOF sticks: every later `readN` keeps yielding `Ok(null)`.
- `read` and `readN` divide the same job: `read` takes all the rest in one string, `readN` takes it in pieces when the whole would be too much to hold.

```js
match std::io::readN(4096) {
  Result::Ok(null) => null             // end of input
  Result::Ok(chunk) => std::io::println(chunk)
  Result::Err(e) => std::io::eprintln(e.message)
}
std::io::readN(0)    // Err — outside 1 …= 16777216, before any block
```

## Failure Model

| Kind | Members |
|------|---------|
| Fallible (`Result`) | every member but the probes — `print`, `println`, `eprint`, `eprintln`, `flush`, `readLine`, `read`, `readN` |
| Absence (`Ok(null)`) | `readLine` and `readN` at end of input |
| Total | `stdinIsTTY`, `stdoutIsTTY` |
| Runtime failure | none — this module states no argument domain that stops the program (`readN`'s `max` domain is an `Err`, not a runtime failure) |

## Checked Call Examples

```js
std::io::print("x")                    // ok
use std::io as io;
io::println("y")                       // ok: the same member, aliased
std::io::print(42)                     // error[E0202]: expected `string`, found `int`
std::io::flush(1)                      // error[E0207]: expected 0 arguments, found 1
std::io::stdoutIsTTY()                 // ok: an ordinary bool — no Result
std::io::readN(4096)                   // ok: Result<string?, Error>
std::io::readN("4096")                 // error[E0202]: expected `number`, found `string`
use std::io as print;                  // error[E0601]: prelude intrinsic name
std::io::writelines(["a", "b"])        // error[E0601]: no member `writelines`
```
