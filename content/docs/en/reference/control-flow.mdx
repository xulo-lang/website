## `if` Expressions (Rust/Swift style)

```js
let max = if a > b { a } else { b }

if condition {
  // ...
} else if other {
  // ...
} else {
  // ...
}
```

When used as an expression, the trailing expression types in both branches must be compatible (otherwise an "incompatible types" error occurs).

## `for` Loops (Swift style)

```js
for item in items {
  print(item)
}

for i in 0..<10 {     // Range (left-closed, right-open)
  print(i)
}
```

## `while` Loops

```js
let count = 0
while count < 10 {
  count = count + 1
}
```

## `match` (Rust style)

```js
match value {
  0 => "zero"
  1 => "one"
  _ => "other"
}
```

- The trailing expression types across all arms must be mutually compatible (same rule as `if` branches); incompatible types cause a static error
- Branches are separated by optional commas or newlines; both work
- Generic enum payloads (`Result<T> { Success(T) ... }`) are erased to `any` inside arms, allowing safe type merging with other branches
- Supports enum member and payload binding:

```js
let result = Result::Success(42)
match result {
  Result::Success(value) => print("Got: " + value)
  Result::Error(msg) => print("Error: " + msg)
}
```

## Error Handling: `throw` / `try` / `catch`

```js
async fn fetchUser(id: string): User {
  try {
    let response = await fetch("/api/users/" + id)
    return await response.json()
  } catch (e) {
    print("Error: " + e.message)
    return null
  }
}
```

- `throw <expr>` throws an exception
- `try { ... } catch (e) { ... }` catches an exception
